# Samsung Galaxy A90 5G

**English** · [한국어](A90.ko.md)

## Device / SoC / kernel

- Device: Samsung Galaxy A90 5G (`SM-A908N`, board codename `r3q`).
- SoC: Qualcomm SM8150 / Snapdragon 855 (`msmnile`).
- Kernel: Samsung vendor Linux 4.14.190. Most established native-init results
  used the stock kernel with a custom ramdisk; the self-built-kernel track is a
  newer and still bounded frontier.

## Role

The A90 is the project's mature native-runtime and Debian-server research
target. Native PID 1 brings up vendor-kernel hardware and remains the recovery
supervisor. The selected product architecture keeps Wi-Fi under native
ownership and gives one isolated child its own PID, mount, IPC, UTS, and
network namespaces before that child becomes Debian PID 1.

## Proven capabilities

- **PROVED — native PID 1 and resident recovery model.** The device has booted
  a static custom `/init` as PID 1, exposed a bounded resident command/runtime
  surface, and returned to known resident health in multiple separately
  journaled runs.
- **PROVED — USB ACM and NCM.** Native boots have exposed the A90 ACM identity
  and a composite NCM path. Bounded health runs proved serial control, direct
  NCM, host/device IP reachability, and the TCP control path. ACM numbering is
  not treated as stable across epochs.
- **PROVED — native Wi-Fi.** Separate bounded experiments brought up the
  internal ICNSS/qcacld WLAN path through association, DHCP, and IP traffic.
  Later evidence showed native Wi-Fi ownership is structural for the selected
  Debian architecture.
- **PROVED — native audio.** Bounded live runs materialized the SM8150 audio
  card, replayed the required calibration and route, wrote and drained PCM to
  the internal speaker, cleaned up the route, and returned through the exact
  rollback path.
- **PROVED — bounded Debian handoff runs.** Individual journaled runs proved
  Debian `sysvinit` as PID 1, key-only Dropbear SSH, native DRM release,
  Debian DRM master/`SETCRTC`, automatic native return, cleanup, and final
  resident health. These are run-specific results, not standing authority.

## Partially proven / observed

- **observed — Debian networking, SSH, Wi-Fi, and display exist as real live
  capabilities**, but their strongest evidence is distributed across different
  bounded experiments. The repository explicitly forbids combining those runs
  into a new persistent-server PASS.
- **PROVED only as a mechanical boundary — direct UFS handoff.** H16 reached
  `switch_root` from the read-only UFS appliance without the old multi-gigabyte
  SD work copy. That run did not prove authenticated SSH, final Wi-Fi, Debian
  PID 1, display, or full persistent-server readiness.
- **designed — isolated Debian successor.** The namespace, minimal `/dev`,
  resource-control, key handling, evidence, cleanup, and native-Wi-Fi boundary
  are extensively specified and host-reviewed. The complete architecture has
  not been implemented and proved in one live terminal run.
- **observed — H34 boot-loop correlation.** Host analysis proved that H34
  omitted `rtic_mp` while retaining a stale stock RTIC DTB. That artifact
  inconsistency is a strong causal candidate, but exact device-side RTIC/QHEE
  causality is unproved.

## Not yet proven

- One persistent isolated-Debian run closing all of: Debian PID 1,
  authenticated SSH, final native-owned Wi-Fi, the selected no-PTY four-node
  `/dev`, namespace isolation, bounded resource behavior, recovery, and final
  health.
- Boot acceptance or functional equivalence of the current public-MPGen
  self-built kernel.
- Exact equivalence between the public MPGen producer and Samsung's stock
  producer, or acceptance of its measurement metadata by proprietary
  RTIC/QHEE components.
- Any new H36 candidate, approval, or live authority. H35 never booted; its
  pre-write failure is not evidence against the packaged kernel.

## Current frontier

The frontier is the self-built 4.14.190 kernel and its RTIC/MPGen production
closure. Exact Snapdragon LLVM 10.0.7 can reproduce the unchanged CFP/JOPP/ROPP
configuration. The repaired public MPGen path now deterministically locates
the required kernel objects, emits task offsets `88/1704/1728/2144`, produces
byte-identical builds, and generates an RTIC DTB whose `MP_DATA` matches the
embedded `rtic_mp` bytes.

That is **PROVED host-side structural consistency**, not a boot result. H35's
package was reviewed as a bounded canary but the live transaction failed
before any candidate write, so H35 remains **unproved** and non-replayable.
There is no successor identity or standing authority. Separately, the product
frontier remains the smaller native-Wi-Fi/isolated-Debian architecture rather
than revival of an older shared-namespace design.

## Major milestones

1. Native static `/init` became a stable resident PID 1 with ACM control and
   recovery-safe boot-only iteration.
2. USB expanded from ACM to composite NCM and bounded TCP control.
3. Native internal WLAN reached association, DHCP, and IP traffic.
4. Native audio reached calibrated internal-speaker PCM playback and cleanup.
5. Bounded handoffs proved Debian PID 1, SSH, DRM/display ownership, return,
   and cleanup in specific runs.
6. Direct read-only UFS handoff removed the earlier SD work-copy dependency.
7. The self-built-kernel track recovered the exact compiler and closed the
   public-MPGen locator/RTIC structural defects; live acceptance remains open.

## Architecture summary

```text
bootloader
  -> Samsung 4.14.190 vendor kernel
    -> native static /init (host PID 1, hardware/recovery supervisor)
      -> ACM + NCM control/observation
      -> native-owned Wi-Fi and required vendor hardware bring-up
      -> isolated child namespaces
        -> read-only UFS Debian root
        -> Debian PID 1 + minimal /dev + authenticated SSH
```

The final two Debian lines describe the selected architecture. Earlier runs
proved important pieces, but not this entire steady state in one run.
