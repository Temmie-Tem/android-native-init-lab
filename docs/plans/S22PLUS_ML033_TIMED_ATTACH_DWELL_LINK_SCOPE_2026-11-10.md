## Prepared use of the existing cue

The retained ML032 host journal records its exact candidate USB descriptor at
N+180.621 seconds and NCM registration at +180.685 seconds, beyond the original
120-second observation. This supports late host enumeration, not authenticated
PID1, a measured physical reconnect time, five-minute survival or UFS proof.
It motivates a prospective timely-attachment experiment without changing the
guest or extending a deadline.

Before N, load the existing CLI and prepare the exact operation path and
non-overwriting private captures for both streams and exit status. Explain
the possible physical action beforehand, explicitly saying to act only on the
actual displayed cue. Aim to invoke the caller around N+25 seconds, while all
existing runtime conditions hold. That timing is operational planning, not
proof that the UDC is bound, a new admission gate or authority to issue blindly.

Raw-complete N, completed installation, the active original window with more
than 60 seconds remaining, current exact ENOENT/no-child evidence, no selected
endpoint or request, no stop/return/terminal/active transfer and matching
grant/consumption/F1 owner remain mandatory. The unchanged caller performs
both owner/source/artifact guards before selecting the latest complete census,
then the final state/latest/raw-integrity/deadline checks. No new observation,
background worker, lease, retry authority or time extension is introduced.

Display only `CUE_RECORDED_DISPLAY_NOW`, immediately with more than 60 seconds
remaining: detach the phone end once for about three seconds and reconnect
once using the same cable, host port and orientation, without buttons. Request
an immediate completion reply; completion by about N+55 seconds is a diagnostic
aim, not a runtime gate or a measurement of physical contact. Nonzero exit,
output failure or `CUE_RECORDED_DO_NOT_DISPLAY` supplies no instruction or
automatic retry. Preserve any durable cue. Resolve only the operator's actual
completion/cancellation through its original interlock before any separate
physical Download instruction. Silence is not resolution.

## Interpretation and adoption

Record first endpoint selection and authenticated base separately from the
same-boot dwell, permit, link and return results. An in-window authenticated
base proves that stage prospectively; it does not prove the historical cause
of ML030–ML032. An operator reply alone cannot measure attachment. A late or
absent connection remains nondiagnostic for a deterministic kernel regression.
Any optional post-closure host-journal comparison must join the actual host
boot and clock offset and remain distinct from authenticated protocol evidence.
USB descriptors alone never upgrade the terminal result.

ML033 requires its own reviewed common/target adoption, exact artifact admission
and current owner/bridge binding. Fresh target/health/rollback checks, usable
Download recovery, the returned exact finite approval and current physical
attendance remain required. No old approval or consumed record transfers.
