# S22+ mainline RAM/USB owner integration — 2026-10-28

The existing V3 Session now has one `mainline-ram` operation. It reuses the
target lease, consumed-candidate registry, boot-only transfer, physical
original-A return and fixed Android health. A dedicated mainline task/profile
and USB observer connect the retained qualified image to those primitives.
No candidate rebuild or device transfer was needed for this integration.

## Behavior and scope

The graph is Android health/Download, one candidate transfer, one authenticated
USB observation, attended physical Download, one original-A transfer and final
rooted Android health. It has no vendor-native baseline admission, storage
command, native_data mount or installed Debian execution. The existing
boot-journal work and retained M=40 issue remain outside this unit.

The mainline observer uses the reviewed USB2 companion lane, exact descriptor
and NCM identity, a task-owned temporary NetworkManager profile and a socket
bound to the selected interface/source. Its window starts at the original N
launch. It records the nonce/request and complete or partial response before
parsing. There is one connection and no request retry after uncertainty.
Authentication, PID1 measurement, kernel release and live DT checks reuse the
retained protocol verifier through a sealed-capture entry point.

Normal A return uses the physical-return request's deadline. A stopped or
interrupted operation can only rederive original evidence or follow the
existing original-A recovery. A completed A permits health handling without
another transfer; an uncertain A does not replay. Candidate/key/network-tool
availability is not an original-A recovery prerequisite. Owned network cleanup
follows A handling and cannot prevent it.

The [adopted policy](../operations/S22PLUS_MAINLINE_RAM_V1.md) requires one
exact returned, attended, 1800-second/one-operation grant. H0 preparation
creates no grant. The named preapproval D0 obtains fixed current Android
health and a durable journal before approval; a grant binds that raw evidence
and the latest completed same-host readiness. Mainline dispatch bypasses
unrelated vendor selectors, keeping the selected execution closure explicit.
