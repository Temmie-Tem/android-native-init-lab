# S22+ FYG1용 Debian 원격 저장소·TFTP 동시 서비스 시험

ML053 기반 ARM64 VM의 한 부팅에서 SysV PID 1이 Debian `rmtfs`와 `tqftpserv`를 시작했다. 한 합성 원격 노드가 같은 GLINK `IPCRTR` 채널로 두 서비스의 광고를 받고 각각 데이터를 읽었다. 정상 시험에서는 원격 저장소 파일 세 개의 핸들을 연 채 TFTP로 FYG1 배포 파일 전체를 받은 다음, 기존 핸들 세 개를 모두 정상적으로 닫았다.

## 펌웨어 디렉터리의 게시 순서

기존 초기 램디스크의 `/lib`는 `usr/lib`를 가리킨다. 이전 TFTP 단독 시험처럼 부팅 전에 `/lib/firmware/modem_pr`를 만들면 28개 펌웨어를 받는 수신기의 목적지가 이미 생긴다. 수신기는 목적지 경로가 존재하지 않을 때만 시작하며, 검증한 임시 디렉터리를 그 자리에 게시한다.

별도 RAM 아카이브에 583,456바이트 TFTP 파일을 `/usr/lib/fyg1-tftp/modem_pr/so/847_f_0.mbn`으로 넣었다. SysV가 기존 수신기의 종료를 기다리고 두 서비스 시작 프로그램을 한 번씩 실행한다. TFTP 시작 프로그램은 게시된 RAM 디렉터리와 `modem.mdt`를 확인한 뒤 그 안에 고정된 `modem_pr` 링크를 만들고 Debian 배포 서버를 실행한다. 게시 성공은 수신기가 검사한 28개 파일에 적용된다. 별도로 담은 TFTP 파일은 아카이브를 만들 때와 상대가 받은 뒤에 각각 CP 원본과 SHA-256을 대조했다. [Debian SysV의 wait와 once 동작](https://manpages.debian.org/trixie/sysvinit-core/inittab.5.en.html)

기존 펌웨어 수신기·인증 형식·송신 파일 목록과 `rmtfs` 시작 프로그램의 바이트를 보존했다. TFTP 단독 시험의 libc·로더는 기존 아카이브와 해시가 달랐다. 기존 libc·로더·QRTR 라이브러리를 사용해 배포 서버의 라이브러리 연결을 검사한 뒤 실제 VM에서 실행했다. 추가한 배포 실행 파일은 `tqftpserv` 1.1-4이고, 추가한 배포 라이브러리는 `libzstd.so.1`이다. [단독 TFTP 시험](S22PLUS_FYG1_DEBIAN_TFTP_H0_2026-11-22.md) · [기존 SysV 저장소 시험](S22PLUS_FYG1_SYSV_RMTFS_H0_2026-11-22.md)

## 같은 아카이브로 부팅한 세 조건

| 조건 | 28개 펌웨어 게시 | 원격 저장소, 서비스 14 | TFTP, 서비스 4096 |
| --- | --- | --- | --- |
| 정상 입력과 준비된 저장소 메모리 | 성공, 호스트 완료 HMAC 일치 | QMI 응답 11건, 순정 순서의 읽기 4건 | 전체 파일 76블록 수신, 해시 일치 |
| 저장소 메모리 드라이버 연결 지연 | 성공, 호스트 완료 HMAC 일치 | 백엔드 확인 단계에서 정지, 서비스 조회 결과 0건 | 같은 파일 76블록 수신, 해시 일치 |
| 마지막 송신 파일의 한 바이트 변형 | 게시 0건, 완료 HMAC 없음 | 펌웨어 확인 단계에서 정지, 서비스 조회 결과 0건 | 같은 단계에서 정지, 서비스 조회 결과 0건 |

정상 부팅에서 네 번의 저장소 읽기 결과는 기존 시험의 전체 공유 버퍼 해시와 각각 일치했다. 네 번째 읽기 뒤 원격 상대가 TFTP로 파일 전체를 요청했고, 583,456바이트를 대조한 뒤 QMI 닫기 응답 세 건을 받았다. 두 데몬은 요청 전후에 각각 같은 PID로 관측됐다. TFTP가 성공한 두 부팅에서 커널에 등록한 VM 시험 프로세서는 읽기 전후 모두 `offline`이었고 시작 호출 횟수는 0이었다.

이로써 저장소 백엔드가 지연된 부팅에서도 파일 서비스의 광고·읽기 성공을 따로 판정할 수 있다. 실제 S22+의 SCM 메모리 권한 수락, 기기 고유 저장소 입력, 메인라인에서 FYG1이 보내는 요청은 미확인이다. 이번 단위는 호스트에서 수행했다.

통합 아카이브는 2,988,260바이트다. 기존 Image와 대상 DT로 계산한 부트 외피 여유는 52,066,176바이트였고 검사한 RAM 구간에 겹침은 없었다. 검증 소스·아카이브·모델 DT와 부팅별 원시 기록은 `workspace/private/analysis/s22plus-dual-services.QliFmvKQ/`에 있다. `result.json`이 세 실행과 입력 해시를 연결한다.
