The automatic window kept the original N launch and its 660-second cap. The
Download generation and target were revalidated at original-A dispatch.
No candidate or rollback transfer was repeated. The first Android health
procedure retained a short properties prefix and a failed root-health ADB

line from the earlier prefix matched the final Android boot. Only the
complete second health procedure establishes the healthy return.

The fixed post-closure reader verified the returned Android boot on both
sides of one successful private last_kmsg read with empty stderr. The
complete returned payload was 2,097,136 bytes. The production decoder found
zero intact, damaged or foreign ML050-format records. An independent search
by candidate identifier found zero occurrences and no committed or
prefix-invalidated authenticated record. The boot diagnostics therefore
provide no physical bind outcome or UDC state. Whether the kernel wrote a
record, a guard prevented recording, or the return path lost it remains
unresolved. Apparent Download timing does not identify which guest component
