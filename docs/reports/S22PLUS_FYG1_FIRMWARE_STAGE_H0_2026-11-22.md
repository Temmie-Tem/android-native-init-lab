# S22+ FYG1 펌웨어 수신기를 포함한 초기 램디스크

**ML053에서 분리한 1,946,780바이트 초기 램디스크가 자체 SysV 설정으로 수신기를 시작했다.** ARM64 VM에서 수신기는 USB CDC-NCM으로 FYG1 펌웨어 28개(109,340,422바이트)를 받아 RAM에 게시했다. 게스트 커널이 게시된 MDT와 분할 파일 전체를 다시 읽어 각각의 길이와 SHA-256을 확인했다. 검증한 아카이브의 SHA-256은 `aacc7c91a7581f03b789d66153ffd2e268dd88a6a35e281035ee4949e1a0b0a3`이다.

## 실제로 시작한 프로그램

이전 2,005,257바이트 부트스트랩의 `/init`은 Debian SysV init을 가리켰고, 그 안의 `etc/inittab`은 ML053의 RAM 관측기를 실행했다. 펌웨어 수신 프로그램과 이를 시작한 inittab은 VM 시험용으로 덧붙인 파일이었다. 이전 배치 계산은 그 수신 프로그램의 크기를 포함하지 않았다. [이전 통합 시험](S22PLUS_FYG1_RMTFS_BACKEND_H0_2026-11-21.md)

새 아카이브는 Debian init·로더·라이브러리, 모뎀 관련 모듈 15개와 Debian `rmtfs`를 보존한다. 별도 사본에서 이전 관측기와 전용 UFS 실험 모듈을 제외하고, `etc/inittab`이 `/usr/libexec/fyg1-fw-stage`를 한 번 시작하도록 했다. VM 전용 보조 작업은 별도 `etc/inittab.d` 항목으로 에뮬레이터와 USB 호스트를 준비했다. 추가한 11개 항목 중 본 아카이브와 경로가 겹친 항목은 없었다. 보조 작업은 PID 1과 직계 자식의 실행 파일을 패키지 파일의 장치 번호·inode와 대조했다.

수신기는 한 USB 컨트롤러와 NCM 인터페이스에 바인딩하고 연결 한 건을 받는다. H0 전용 공유키로 매 연결의 난수에 대한 HMAC을 검증한다. 송신자는 파일명이나 목적지를 지정할 수 없다. 수신기는 RAM 파일시스템에서 고정된 28개 이름·길이·해시를 검사하고, 스트림 끝을 확인한 뒤 디렉터리를 한 번에 게시한다. 기존 목적지의 교체는 허용하지 않는다. 게시가 성공하면 수신기는 같은 난수에 응답용 HMAC을 돌려준다.

## 전송 결과

모든 시험에서 메인라인 Image와 본 아카이브의 바이트가 같았다. 정상 시험은 VM의 dummy UDC에 보드에서 기대하는 컨트롤러 이름을 부여해 수행했다. 원래 dummy 이름을 사용한 부팅도 별도로 확인했다.

| 조건 | 호스트 완료 응답 | 종료 후 상태 |
| --- | --- | --- |
| 정상 펌웨어 | HMAC 일치 | 커널이 28개 파일 전부 검증 |
| 마지막 파일 1바이트 변형 | 없음 | 게시·임시 디렉터리 없음 |
| 정상 파일 끝에 1바이트 추가 | 없음 | 게시·임시 디렉터리 없음 |
| 8,192바이트에서 전송 종료 | 없음 | 게시·임시 디렉터리 없음 |
| 잘못된 공유키 | 없음 | 파일 송신 0바이트, 게시·임시 디렉터리 없음 |
| 예상과 다른 UDC 이름 | 연결 전 종료 | 파일 송신 0바이트, USB 네트워크 인터페이스와 게시·임시 디렉터리 없음 |
| 정상 파일 전송 직후 호스트가 완료 응답을 읽지 않고 연결 종료 | 수신 0바이트 | 커널이 게시된 28개 파일 전부 검증 |

별도 정상 전송에서는 호스트가 보관한 난수와 32바이트 완료 응답으로 HMAC을 오프라인에서 다시 계산했다. 연결 종료 대조는 TCP 송신 방향을 닫은 뒤 완료 응답을 읽지 않고 소켓을 닫았다. 따라서 **완료 응답이 없다는 사실만으로 파일이 게시됐는지 판단할 수 없다.** 이 결과는 애플리케이션의 읽기와 커널 파일 조회를 대조한 것이다.

## S22+ 배치와 실기 범위

이전 부트스트랩의 로더 해시와 배치 결과를 재현한 다음 새 램디스크·Image·DT를 실제로 다시 링크했다. 새 로더는 46,107,872바이트다. 로더의 실행·복사 공간, 커널 실행 범위, DT, initramfs는 기존 RAM 뱅크 안에 들어가며 서로 또는 고정 예약 영역과 겹치지 않았다. ML053의 96 MiB 부트 외피 기준으로 53,110,656바이트가 남는다.

이번 아카이브의 기능은 펌웨어를 커널에 공급할 수 있는 위치에 게시하는 데까지다. 실제 S22+의 USB 열거·전송 시간, SCM 메모리 권한, PAS 인증 및 FYG1 기동은 미측정이다. `rmtfs` 서비스 시작과 저장소 데이터 공급도 이 수신기의 작업에 포함되지 않는다. 기존 ML053의 기기 실행·복구 경로는 이 아카이브에 채택하지 않았다. 실기에 부팅하려면 S22+ 대상 계약에 맞는 실행 범위, 정확한 부트 패키지, 복구 경로와 권한이 필요하다.

비공개 근거는 `workspace/private/analysis/s22plus-ml053-firmware-stage.edChuWcV/`에 있다. `package.json`은 실제 컴파일 의존성과 아카이브 항목을, `layout.json`은 재링크한 산출물과 배치를 식별한다. `valid.json`, `altered.json`, `extra.json`, `short.json`, `badkey.json`, `wrong-udc.json`은 첫 여섯 조건의 원시 로그를 가리킨다. 완료 응답 원시 캡처와 연결 종료 대조는 `observed.json`과 `strict-loss.json`에 있다. 독립 H0 검토와 사후 재검산이 확인한 최종 입력·결과 해시는 `close.json`에 있다.
