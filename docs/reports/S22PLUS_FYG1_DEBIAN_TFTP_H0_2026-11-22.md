# S22+ FYG1 파일을 Debian QRTR TFTP로 읽은 ARM64 VM 시험

Debian trixie arm64의 수정하지 않은 `tqftpserv` 1.1-4가 FYG1 배포 파일 `847_f_0.mbn`의 크기와 여섯 구간을 제공했다. 합성 원격 노드가 GLINK의 `IPCRTR` 채널에서 받은 데이터는 79블록, 합계 579,527바이트였다. 구간끼리 겹치는 부분을 포함한 합계다. 수신 측에서 각 바이트를 비교했고, 호스트에서 여섯 수신 해시를 원본 FAT 파일의 해당 구간 해시와 독립 대조했다. [Debian 패키지](https://packages.debian.org/trixie/tqftpserv)

## 시험 환경과 파일 검색

기존 ML053 기반 Image와 SysV 시험 아카이브에 VM 전용 파일을 덧붙였다. 기존 아카이브 바이트와 커널 해시를 확인했다. 서명된 Debian arm64 패키지 인덱스로 서버·로더·라이브러리를 검증했다. 게스트의 합성 상대는 RAM FIFO로 연결한 두 커널 GLINK 끝점 중 한쪽에서 동작했다. 반대쪽에는 `qcom_smd_qrtr`가 연결됐고, 상대가 서버의 서비스 4096·버전 1·인스턴스 0 광고를 수신했다.

먼저 시험용 디렉터리로 서버의 파일 검색을 확인했다. 두 번째 부팅에서는 VM 전용 모듈이 Linux `rproc_add`를 호출해 실제 커널 클래스에 시험 프로세서를 등록했다. 펌웨어 이름 `modem.mdt`와 자동 기동 해제는 ML053의 SM8450 MPSS 드라이버 기본값과 일치했다. 대상 DT에 `firmware-name` 재정의는 없었다. 등록 직후와 전송 종료 후 커널의 `firmware`·`state` 속성은 각각 `modem.mdt`·`offline`이었고 시험 드라이버의 시작 호출 횟수는 모두 0이었다.

같은 서버 프로세스에 같은 파일 크기 요청을 보냈다. `/lib/firmware/modem_pr/so/847_f_0.mbn`이 이미 있어도 커널의 원격 프로세서 목록이 비어 있으면 TFTP 오류 1이 왔다. 목록에 시험 프로세서를 등록하자 서버가 583,456바이트를 응답했다. Debian 서버는 클래스의 `firmware` 속성에서 기준 디렉터리를 구한다. 이 시험에서는 프로세서가 오프라인인 동안에도 파일을 찾았다. [Debian 파일 검색 구현](https://sources.debian.org/src/tqftpserv/1.1-4/translate.c)

## 순정 관측과 VM 수신 결과

R4W1-A Android 부팅에서 DMS 응답 전에 처리한 파일명·요청 길이·응답 통계를 사용했다. VM은 선두에 슬래시가 있는 `/readonly/firmware/image/modem_pr/so/847_f_0.mbn`에 표준 읽기 요청과 Qualcomm 옵션을 보냈다. 블록 크기 7,680바이트, 시간 제한 5,000ms, 창 크기 10을 사용했다. 합성 상대는 반환된 옵션 이름·값, 전송 포트, 연속 블록 번호와 길이를 검사했고, 두 큰 구간에서는 창 단위로 수신 확인을 보냈다. [Debian 서버의 옵션 처리](https://sources.debian.org/src/tqftpserv/1.1-4/tqftpserv.c)

VM에서 없는 파일을 요청하거나 같은 파일명의 맨 앞 슬래시를 빼면 오류 1이 왔다. 두 오류 뒤에도 정상 경로의 크기 요청은 성공했다. FYG8 Android 서버는 파일명을 로그에 쓰기 전에 선두 슬래시가 있으면 한 글자를 건너뛴다. 따라서 보관 로그의 `readonly/…` 표기와 일곱 요청의 길이 일치는 VM에서 사용한 경로와 양립한다. 보관 자료에는 요청 원문 전체가 없어 실제 모뎀이 보낸 첫 글자나 옵션 순서까지 확인할 수는 없다.

초기 메인라인 파일 서비스의 H0 비교에는 이 배포 서버와 CP 파일을 사용할 수 있다. 실제 메인라인 S22+에서 MPSS가 해당 요청을 보내는지와 이 파일이 DMS 응답에 필요한지는 미확인이다. 이번 검증은 호스트에서 수행했다. 비공개 근거는 `workspace/private/analysis/s22plus-debian-tftp.xE9Ig8OG/result.json`에 있다. 두 VM 부팅의 직렬 로그, 패키지 및 원본 해시, 구간별 수신 해시와 검증 소스를 같은 디렉터리에 보존했다.
