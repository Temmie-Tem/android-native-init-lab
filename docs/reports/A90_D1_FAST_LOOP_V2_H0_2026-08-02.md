## Reduced fast loop

The v2 path is:

```text
immutable resident manifest
-> canonical resident journal derived by the runner
-> non-expiring host session template
-> fresh exact duration-and-budget approval
-> opening D0 health/source preflight
-> one durable new action intent
-> one switch_root dispatch
-> return, cleanup, and final resident health
```

The host template binds a positive duration of at most eight hours instead of
absolute timestamps. The exact opening and expiry are created and fsynced only
after fresh approval validation and the opening preflight complete. An unused
template therefore does not expire before the operator starts it, and
preflight time does not consume the newly opened window. Resume fully restores
durable state before connected preflight, then resamples the clock and rejects
an expired window before creating a new action intent.

The builder no longer accepts an independently selected resident journal path.
It derives `f1-live/journal` from the exact resident manifest directory and
still validates all eleven terminal records, the one candidate transfer, zero
candidate replay, zero rollback transfer, and `RESIDENT_HEALTHY` terminal.

Opening health and immutable-source evidence is passed directly to the action
owner. The first action no longer repeats those same two reads immediately
before handoff. NCM, pstore, channel, USB epoch, guard, return, cleanup, final
health, and final source checks remain distinct and bounded.

## Observer-only continuation

`NO_PROOF_OBSERVER` still never causes automatic resend. It requires exact
cleanup, exact resident health, and the independent safety predicate. The
session pauses after the uncertain action.

The operator may explicitly acknowledge that no-proof on a later invocation.
That acknowledgement is journaled in a new ordinal intent, consumes a second
action from the budget, and permits one new dispatch. It is not a replay of the
uncertain action. A second observer-only no-proof with the unchanged observer
closes the session as `SESSION_CLOSED_REPEATED_OBSERVER_NO_PROOF` while keeping
the proven device-safety state separate.

Observer replacement with focused H0 validation remains available in the pure
state engine. The current live adapter still does not invent or auto-apply an
observer repair.
