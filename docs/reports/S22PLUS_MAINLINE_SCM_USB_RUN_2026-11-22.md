# S22+ 실기에서 확인한 메인라인 SCM 드라이버 연결

2026-11-22 입회 부팅에서 SM-S906N/g0q의 지정된 Qualcomm SCM 플랫폼 장치가 메인라인 드라이버에 연결돼 있었다. 판정은 `OBSERVED_SCM_BINDING` / `bound`다. 같은 실행기가 원래 Android를 복원하고 `ANDROID_CLOSED_HEALTHY`로 종료했다. 이 후보와 1회 승인은 소모됐다.

## 무엇을 관측했나

[사전에 검증한 부트 AP](S22PLUS_MAINLINE_SCM_BOARD_ARTIFACT_H0_2026-11-22.md)로 부팅한 Debian RAM 관측기가 CDC-NCM으로 요청 하나에 응답했다. 응답 시점의 커널은 `7.2.11-g0q-ram-h0`, 기기 부팅 경과 시간은 76.258초였다. 지정된 SCM 노드의 첫 드라이버 연결을 판독하는 규칙은 [USB 관측기 보고서](S22PLUS_MAINLINE_SCM_USB_H0_2026-11-22.md)에 있다. 검사한 것은 그 시점의 연결 상태다. 최초 연결 시각은 측정하지 않았다.

호스트에 보존한 72바이트 요청과 500,388바이트 응답을 별도 코드로 다시 검사했다. 요청·응답의 HMAC, 후보 ID, 요청 nonce가 일치했다. 응답의 상태 필드는 `bound`였고, 응답에 딸린 500,000바이트 기기 트리는 로더가 인계하도록 검증한 원본과 바이트 단위로 일치했다. MPSS는 이 기기 트리에서 비활성이었다. 대기열 IRQ의 실제 등록·발생, 개별 SCM 호출의 반환값, VMID 15 메모리 권한 수락과 모뎀 기동은 이번 측정의 범위 밖이다.

## 재연결 진술 보충

운영자는 Download 장치가 호스트에서 사라진 10:47:31 KST와 가젯이 나타난 10:49:09 KST 사이에 폰 쪽 케이블을 한 번 재연결했다고 확인했다. 두 시각은 호스트 관측으로 잡은 구간의 양끝이며 실제 조작 시각은 측정하지 못했다. 재연결은 당시 일반 증거 경로의 cue 발급·완료 절차 밖에서 이뤄진 입회 중 물리 조작으로 기록한다. [운영자 진술 출처, 안건 1](../plans/S22PLUS_MAINLINE_ORDINARY_CUE_AGENDA_2026-11-22.md#안건-1-scm-실기의-기록되지-않은-재연결-담당-codex)

같은 작업의 `operator-replug-addendum-20261122.json`에 진술 출처와 원래 작업·종료 증거의 해시를 연결했다. SCM 인증 응답은 재연결이 보고된 조건에서 얻은 관측으로 해석한다. 원래 Android A 전송과 최종 건강은 기존 기기 증거로 확인됐다.

## 전송과 복구

| 승인 개시 후 경과 시간 | 실행 기록 |
| ---: | --- |
| 16.13초 | 후보 N 전송 완료 |
| 116.24초 | 인증된 SCM 관측 완료 |
| 158.46초 | 운영자가 물리 Download 진입을 확인한 뒤 원래 Android A 전송 완료 |
| 231.97초 | 원래 Android 최종 건강 확인 및 종료 |

후보와 원래 Android는 각각 한 번 전송했다. A 전송 후 첫 건강 판독에서 ADB가 대상을 찾지 못해 실행기가 멈췄다. 기존 소유자가 내구 기록에서 A 전송 완료를 검증한 뒤 건강 판독만 재개했다. 복귀 후 같은 단말·USB 경로, 바뀐 부팅 ID, 정상 루팅 Android 상태, 준비 시점과 동일한 boot·dtbo·recovery·vendor_boot 해시를 확인했다. 관측용 호스트 네트워크 프로파일도 제거됐다.

구조화된 종료 결과와 정식 타임라인은 `workspace/private/outputs/s22plus-scm-usb-attended-h0-20261122-1/task-1/`의 `closed.json`과 `timeline.json`에 있다. 같은 작업의 `raw-index.json`은 보존된 명령 캡처와 연결된다. 독립 응답 대조는 준비 디렉터리의 `independent-wire-check.json`에 있다. [실행 범위와 복구 조건](../operations/S22PLUS_MAINLINE_SCM_USB_V1.md)

다음 모뎀 연구 질문은 고정 RMTFS 메모리에 대한 VMID 15 권한 요청을 펌웨어가 수락하는지다. 이를 알아보려면 요청의 실제 반환값과 메모리를 원래 소유자에게 돌려주는 조건을 별도 실험으로 설계해야 한다.
