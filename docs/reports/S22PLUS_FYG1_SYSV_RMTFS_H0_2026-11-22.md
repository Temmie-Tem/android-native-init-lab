# S22+ FYG1 · 펌웨어 게시 뒤 Debian 원격 저장소 서비스 기동

**2,274,218바이트의 ML053 기반 초기 램디스크가 ARM64 VM에서 자체 SysV 설정으로 Debian `rmtfs`를 시작했다.** 합성 원격 노드가 메인라인 GLINK에서 서비스 14를 발견한 뒤, S22+의 두 FYG8 Android 부팅 기록에서 확인한 네 번의 읽기를 수행했다. 매번 2.5 MiB 공유 버퍼 전체를 검사했고 네 해시가 이전 독립 검산값과 일치했다. 정상 아카이브의 SHA-256은 `8ffae16c436190f64f4a0a4d0d8ff3b05ce677ee53ec822dd3b598bf32245cb9`다. [실기에서 관측한 읽기 범위](../GOAL_S22PLUS_MODEM.md#2026-11-22--두-fyg8-android-부팅의-원격-저장소-읽기-순서와-파일-범위)

## SysV에서 시작한 두 프로그램

주 inittab은 런레벨 2의 `wait` 항목으로 기존 펌웨어 수신기를 실행한다. 수신기가 끝나면 `once` 항목으로 저장소 시작 프로그램을 한 번 실행한다. 이전에 검증한 수신기와 Debian init·데몬의 바이너리는 그대로 사용했다. 초기 아카이브에는 펌웨어 디렉터리가 없고, 수신기만 28개 파일의 길이·해시와 스트림 끝을 확인한 후 디렉터리를 게시한다. 다음 프로그램은 이 단일 게시 경로와 MDT 메타데이터를 확인한다. 별도 VM 커널 검사가 게시된 28개 파일을 다시 읽었다. [수신기 검증](S22PLUS_FYG1_FIRMWARE_STAGE_H0_2026-11-22.md)

시작 프로그램은 RAM에 있는 FSG·FS1·FS2 입력이 지정한 길이와 해시를 가진 일반 파일인지 검사한다. 이번 파일은 각각 3,145,728바이트이며 파일마다 구별되는 합성 데이터를 담았다. 이미 연결된 RMTFS 백엔드의 DT 경로·드라이버·문자 장치 부모와 클라이언트 ID·기준 주소·크기를 확인한 뒤, 별도 마운트 네임스페이스에 그 문자 장치를 고정한다. 패키지의 QRTR 모듈을 준비하고 배포판 데몬을 `-r` 파일 모드로 실행한다. 데몬은 시작 프로그램과 같은 PID로 실행된다. `-r`은 파일의 RAM 사본을 사용하는 옵션이다. 이 시험에서 원격 상대가 요청한 작업은 읽기였다.

VM 시험 장치가 커널에 가상 예약 메모리와 두 GLINK 끝점을 제공하고 RMTFS 메모리 모듈을 적재했다. 정상 대조에서는 VMID 속성을 생략했다. 지연 대조에서는 VMID 15를 유지하고 SCM 공급자가 없는 상태로 부팅했다. 시작 프로그램은 SCM 권한을 요청하거나 MPSS를 기동하지 않는다. 첫 드라이버 연결 전후의 sysfs 상태를 관측한 결과는 이 커널과 이 부팅의 근거다.

정상·응답 유실·백엔드 지연·펌웨어 변형은 같은 아카이브를 썼다. 저장소 입력 세 대조는 입력 파일만 달랐다. 두 성공 부팅에서는 직접 관측한 프로세스가 SysV PID 1의 자식이었고, 데몬의 실행 파일·인자·전용 장치 네임스페이스가 모두 일치했다. 원격 상대가 받은 11건은 열기 3건, 할당 1건, 읽기 4건, 닫기 3건이다. 마지막 읽기는 FS1의 오프셋 1,024에서 2,620,416바이트였다. 다섯 정지 부팅에서는 해당 시작 프로그램의 사유, 데몬 부재, QRTR 이름 서비스의 빈 조회 응답을 함께 확인했다.

첫 시험은 VM 보조 프로그램이 `sysinit`에서도 부모 PID 1을 요구해 시간 초과했다. Debian init 3.14-4는 초기화 단계의 대기 작업에 중간 자식을 둔다. VM 보조 프로그램의 시작 조건을 고친 뒤 재실행했다. 본 아카이브의 수신기와 저장소 시작 프로그램에는 직계 부모 및 PID 1 실행 파일 확인을 유지했다. [Debian init 소스](https://sources.debian.org/src/sysvinit/3.14-4/src/init.c/#L1177)

## 남은 실기 조건

최종 Image·대상 DT·정상 아카이브를 다시 링크했다. 기존 RAM 배치에서 네 구간의 충돌은 없었고 96 MiB 부트 외피에 52,782,976바이트가 남았다. 메인라인 S22+에서 필요한 실기 증거는 고정 RMTFS 메모리 권한의 실제 수락과 FYG1 노드의 실제 요청이다. 이 아카이브의 합성 입력을 실기 모뎀 데이터로 쓸 근거는 없다.

FYG8 배포 표가 MODEMST1·MODEMST2·FSG에 지정한 플래시 파일은 각각 `nvrebuild1.bin`, `nvrebuild2.bin`, `nvrebuild3.bin`이다. 보관한 공장 펌웨어 ZIP에서 AP·BL·CP·CSC·HOME_CSC의 크기와 SHA-256을 검증하고, 각 Odin 아카이브에 직접 들어 있는 일반 파일 55개를 확인했다. 세 이름은 압축용 `.lz4` 확장자를 제외하고 대조해도 발견되지 않았다. 이 결과는 배포 표에 지정된 파일이 직접 공급되는지에 대한 판정이다. 파티션 내부의 다른 파일이나 기기별 저장소 내용을 조사한 것은 아니다. 파일별 대조는 `factory.json`에 있다.

비공개 근거는 `workspace/private/analysis/s22plus-ml053-sysv-rmtfs.WKv8YAj6/`에 있다. `package-valid.json`과 `layout.json`은 아카이브·실행 파일·배치를 식별하고, `normal.json`과 `lost.json`은 GLINK 거래·버퍼 해시 및 원시 로그를 가리킨다. 다섯 정지 결과와 독립 H0 검토에 사용한 입력은 `close.json`에 함께 기록했다.
