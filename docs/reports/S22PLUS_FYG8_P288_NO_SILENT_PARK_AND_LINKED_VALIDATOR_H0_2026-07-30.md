## Result

The formal post-build proof introduced by commit
`6fc2881e2abe22161a66ce130fc4c10bf430a4bf` did run and pass before
promotion. It strongly rejects a source/table validator mismatch as the cause
of the missing generation 89:

- the host-native replay evaluated all `6,815,744`
  `(generation,stage,item_index)` inputs against the unmodified production
  validator functions and accepted exactly the declared 103 positions;
- the post-build audit compared the four linked ELF tables with the exact
  source-generated bytes; and
- the independent candidate-static checker reran that audit fresh, required
  exact result equality, and closed as
  `PASS_P288_INDEPENDENT_ARTIFACT_CLOSURE_HOST_ONLY`.

That proof does not cover runtime publication return values or synchronization
between the retained record, the kernel writer state, and the userspace
checkpoint client. Publication rejection remains a priority cause class, but
this H0 does not prove that it caused the live stop.

The earlier claim that P2.88 proved a no-silent-park invariant is false.
P2.88 proves only that every raw park is topologically behind a wrapper that
*attempts* an exact or reserved-unclassified publication. Both wrappers discard
the fallback publication result:

```c
static void quiet_park(void) {
    (void)s22_p288_checkpoint_unclassified_next(&g_checkpoint);
    p288_raw_quiet_park();
}
```

If the primary publication and the fallback both fail, execution reaches the
raw park with no new retained record. That is a concrete silence-producing
control-flow path. It is compatible with the retained shape, but compatibility
is not live causation.

No new F1 is justified by this H0.

## Exact generation-88 publication return semantics

The retained generation 88 proves that its slot body and commit CRC reached
the retained medium. Exact source further narrows what may happen afterward.

The kernel writer orders:

```text
target CRC commit
post-commit header/slot verification
in-kernel active_slot/generation update
return full request count
```

The post-commit verification can return `-ESTALE` after the target CRC is
committed but before the in-kernel state advances. There is no source error
return after the in-kernel state update.

The userspace client orders:

```text
sys_write
sys_close
write-length check
close-result check
local generation update
```

The exact common-kernel close path rejects the earlier close-error
counterexample. `filp_close()` obtains a nonzero return only from
`file_operations.flush`; `proc_reg_file_ops` has no `.flush`, and the
checkpoint `proc_ops` has only `.proc_write` and no custom release. A valid
single close after a successful checkpoint write returns zero.

Consequently, exact source does not support “kernel state advanced but
userspace stayed on the previous generation because close failed.” If the
kernel returns post-commit `-ESTALE`, both the kernel writer state and the
userspace client still target the same next generation. The fallback is not
sequence-stale; it may overwrite the same target slot with an unclassified
generation-88 failure if it succeeds.

The live retained record is still the progress generation 88. It therefore
proves that no fallback successfully committed a later or replacement failure
record. It does not distinguish:

- a non-returning operation before the next commit;
- a primary publication error followed by a fallback error; or
- another runtime publication-state failure not covered by the static
  validator proof.

## Generation 88 to 89 exit enumeration

Starting at the generation-88 ring commit, the exact returned branches are:

| Boundary | Returned result | Evidence route |
|---|---|---|
| generation-88 kernel post-commit check | success | kernel state advances and write returns full count |
| generation-88 kernel post-commit check | `-ESTALE` | `p282_progress()` receives error, then generic unclassified fallback is attempted |
| exact procfs close | success only | client advances to generation 88 |
| restart `clock_gettime` | error | `p282_cycle_abort()` attempts an exact generation-89 failure |
| next-position lookup | error | generic unclassified generation-89 fallback is attempted |
| any of 12 gates | returned error | `fail_at()` attempts exact generation-89 gate detail, then unclassified fallback on error |
| generation-89 progress publication | success | generation 89 survives |
| generation-89 progress publication | error | generic unclassified generation-89 fallback is attempted |

In every failure row, a *successful* exact or fallback publication produces a
new retained record. The uncovered exit is the same in each row:

```text
primary publication returns error
  -> fallback publication returns error
  -> fallback return is discarded
  -> raw quiet park
```

Non-returning syscalls are not exits and cannot be transformed into evidence
by a later wrapper. This enumeration therefore refutes, rather than proves,
the requested absolute invariant.

## Why the pre-live park gate passed

`_audit_park_routes()` checks:

- the raw sink appears only in the two wrapper functions;
- every source layer still contains routed `quiet_park()` calls;
- the generic wrapper text contains an unclassified publication call; and
- the pre-init PID/client guards retain their expected shape.

It then returns the literal claims
`raw_sinks_publication_dominated=True` and
`unclassified_before_generic_park=True`.

The first claim is too strong. The gate proves call topology and publication
attempt, not a successful retained commit. It neither captures the fallback
return nor checks it before entering the raw park. The earlier focused test
therefore passed while the absolute no-silent-park property remained false.

This is a proof-scope defect in an identity-external verifier, not a mutation
of the closed P2.88 candidate.

## Consequence

The current evidence ordering is:

1. asynchronous candidate-time reset remains rejected;
2. pair numbering and linked validator/table agreement are proven;
3. ordinary returned gate failure is not an independent recordless cause;
4. successful-write/close client divergence is rejected by exact source; and
5. publication non-return or primary-plus-fallback failure remains unresolved.

A successor must not merely add another marker after the same fallible
publisher. Before another F1 it needs a mechanically checked policy for
publication failure that does not claim successful evidence from a discarded
fallback return, plus the intended adjacent corridor positions. If the sole
retained channel cannot report its own persistent failure, that limitation
must be stated explicitly rather than labeled no-silent-park.
