# S22+ late-UFS preparation and return improvements

Status: **H0 COMPLETE / INDEPENDENT PASS_GO — NOT LIVE-ADOPTED**.

The isolated `codex/s22-mainline-efficiency-h0` branch extends the completed
stage-two diagnostic unit. It implements the two subsequently selected
improvements: a narrow pre-effect normal-return class, and key-only candidate
qualification against a reusable capability. It performs no connected read,
control, transfer, live activation or new physical experiment. The original
checkout, its unrelated Debian journal work, and A90/S20+ remain separate.

## Pre-effect return boundary

The certificate is set only after the actual coverage call refuses before
any overlay dispatch, with no USB reference, stage-two work, fixed RPMh record
or error, and after the actual RPMh arena teardown. The internal coverage path
may acquire and unwind USB/PM references; the certificate does not claim that
no device activity of any kind ever occurred. It certifies the narrower
absence of the late UFS work and settlement required by this return class.

The explicit v4 mode retains the 23-field/256-byte report. A format tag and
certificate occupy reserved high bits of the stage-two site field; lower
stage-two site semantics remain unchanged. The module, guest gate and host
parser must all select the matching mode. Legacy v1–v3 interpretations do not
inherit the extension. Overlay/probe failure, stage two, missing/unknown state,
malformed authentication, bad acknowledgement and deadline expiry continue
to stop normal return. A successful return after refusal preserves UFS
`NO_PROOF`, independently from original-A recovery and health.

The new class uses the existing complete-result digest, nonce, durable intent,
EOF and last-moment deadline checks. It adds no reconnect, control retry,
transfer retry, effect budget or deadline extension. Earlier consumed reports,
source provenance, approvals and journals are unchanged.

## Capability and qualification

The [V2 H0 specification](../operations/S22PLUS_MAINLINE_UFS_CAPABILITY_V2.md)
defines the exact fixed and variable inputs. Candidate declarations provide
receipts for a manifest, producer, loader, package and fresh loader tests, plus
the shared capability and review. They contain no executable review selector,
report-mode override or arbitrary policy scope. `profile.image_binding()` and
the existing task preparation/validation route select the new schema; v1
retained declarations remain intact.

The capability pins current common/target authority and the selected source
closure. Per-candidate historical UFS policies are excluded from V2 authority;
the shared unadopted policy is selected instead. Marker helpers remain pinned
because the existing loader still eagerly imports and uses their format table
on the unmarked path. File-count reduction is not the acceptance criterion.

Each candidate reproduces the complete observer ELF with its key, generated
source and seal. Actual compiler dependencies include system headers, compiler
and linker tools and their host libraries, startup objects and static archives.
The final checker separately measures the declared linker plugin/wrapper and
effective GCC specs before and after complete reproduction. Original builder
receipts retain their original input set; their final bytes are re-proved with
the expanded fresh checker provenance.
Canonical CPIO checks preserve package bytes, modes, links, inittab and module.
The qualifier checks actual AP decompression, boot envelope, loader bytes and
embedded fixed kernel/DTB/archive. Kernel release, network addresses and loader
kernel path cannot be smuggled in as variable candidate metadata.

Reproduction and byte-join work run during fresh H0 qualification, outside the
owner's timed window. Session validation checks immutable qualification joins,
source and artifact identity; it never compiles or starts QEMU. Large immutable
files use the existing file-identity-aware `unchanged()` verification rather
than a new cache framework. A changed file identity causes re-verification.

Task preparation snapshots the selected review and capability. Original-owner
recovery reads those immutable metadata records without importing the V2
candidate validator or requiring candidate keys, packages, compiler files or
new qualification. Existing eager owner dependencies remain required. The
H0-only task integration fixtures use synthetic retained target/A facts; they
do not relocate, repin or reinterpret the real device's recovery evidence.
