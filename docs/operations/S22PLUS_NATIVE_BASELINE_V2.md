# S22+ attended resident native baseline V2

Status: **REVIEW_GATED_CAPABILITY; H0 only before current independent review,
exact attended grant and live bootstrap admission.**
Target: **SM-S906N / g0q / S906NKSS7FYG8**.

This is a separate common-incorporated permanent-boundary exception. It defines
normal `N -> E -> N` operation with an admitted resident native baseline N,
a distinct globally one-shot experimental native image E, and one exact Android
A exit/fallback per operation. It preserves the bytes, policy pin, claims,
approvals and consumed evidence of native baseline V1 and P383/P384/P385/P386.
The P386 checkpoints are evidence about its resident runtime, not admission of
that consumed candidate to this lane. The first new declarations are P387
(`v0.2.0-rc.5`) and P388 (`v0.2.0-rc.6`); each requires its own artifact/static
qualification and exact live role binding.

## Identity and admission

The shared baseline owner selects V2 only from an exact `native-baseline-v2`
request in its separate private V2 run root. The request binds N's complete
manifest, AP/member, runtime/source profile, key/run identity and host execution
closure. An experiment request also binds E's separate complete manifest,
AP/member, runtime/source profile, key/run identity and host closure. Both
manifests must bind one identical exact Android A. N is never placed in E's
ordinary `rollback_ap`. The closed declaration catalog selects the resident
wire profile and the baseline descriptor owner; the thirty-minute P386 owner
is a different profile.

Bootstrap begins from fresh exact rooted FYG8 Android health. It installs one
previously unconsumed N, proves fixed native health, clean DETACH and fresh
same-boot reauthentication, observes its exact timely CONTROL/Download return,
then performs one separately intended same-N qualification restoration. The
second boot must pass health, clean same-boot reauthentication, final DETACH and
actual descriptor close. Only the complete rederived `NATIVE_CLOSED` terminal
admits that exact native content, byte-source closure and physical target.
The original installation claim remains permanently consumed. Bootstrap cannot
be used to replay an admitted or otherwise consumed image.

An admitted N may subsequently be installed/restored only in a declared normal
baseline role under this finite owner. Its admission is rederived from the
original complete live qualification and permanent global claim. A host-only
repair may retain admission only while native byte inputs and artifacts are
unchanged and the current reviewed reader rederives that proof. Host review and
native admission remain separate. Every normal role keeps its own consumed
intent; admission never releases a claim or turns a failed E into a baseline.

Native admission binds the selected declaration's namespace, run/version,
Image and key identity, resident profile and actual native byte-source inputs.
The whole declaration catalog belongs to current host review, not N's native
byte identity. Adding a future E therefore requires renewed host review without
changing an otherwise identical admitted N. A changed selected N or native byte
source still fails that admission comparison.

## Finite attended operations

One separately returned exact approval binds the target, current reviewed
sources, N/E/A identities, requested operation set and limits. A grant permits
at most three operation reservations and 600 host `CLOCK_BOOTTIME` seconds;
smaller limits are allowed. Physical attendance and demonstrated usable exact
physical Download recovery remain required. Preparation and capability PASS_GO
are H0 and never create a grant. An ended grant is not standing recovery
authority for a later native snapshot.

The operation set is `bootstrap`, `restore`, `experiment` and `android-exit`.
Bootstrap has two native roles; restore has one normal N role. Experiment must
start from an admitted N terminal and contains exactly one E installation and
one normal N restoration. Each operation shares one exact A role between direct
Android exit and failure fallback. The target lease and durable F1 owner
serialize effects; an unresolved operation blocks the next reservation.

Before leaving N, the owner reopens both current native bindings and rejects
equal N/E run identity, equal AP/member content, or already consumed E content.
Fresh authenticated N health must prove the retained N boot, precisely the next
signed authentication ordinal and a new nonce. The operation exclusively
consumes the previous terminal's successor link. The present tty must match its
exact target/endpoint and current guard properties. Cached health alone cannot
authorize a departure, transfer or new authentication after a stop.

Only after N's complete health and exact timely CONTROL/Download does the owner
atomically claim E through the existing global content registry immediately
before its sole installation role. A changed path, manifest, grant or later
healthy observation does not make E fresh. N's admission exception never covers
E. Intent, delivery and immutable raw result remain distinct one-shot records.

The initial declared E workload is two bounded fixed native-health
authentications separated by clean DETACH and actual close/reopen. Its optional
bounded resident HUD export is retained separately and proves neither physical
pixels nor continuous liveness. This owner admits no caller-selected root
command or arbitrary experiment plan. Extending the workload changes the
reviewed declaration/observer scope.

Normal E-to-N restoration requires completed E transfer, its authenticated new
boot, complete declared health workload, and exact Download arrival inside the
original CONTROL window. The returned N must match its prebound admitted
artifact and have a boot distinct from both starting N and E, with fresh nonces,
complete health, clean reauthentication and final DETACH/descriptor close. A
failure or uncertainty never substitutes a new native attempt for this proof.

## Resident lifetime and terminal evidence

The selected resident runtime has no normal-service lifetime ceiling. It uses
the existing signed INFO-v2 64-bit authentication ordinal, ordinal-bound nonce,
cached preparation and exhaustion behavior. The host rejects exhausted clean
reentry and requires at least one future authentication slot at native close.
It does not apply baseline V1's eight-authentication/900-second ceiling or
invent a replacement service timer. Returning to N creates a new native boot;
it does not renew any host grant.

Each observer remains bounded by 60 seconds, each command retains the existing
native command/session/output limits, and every device write is bounded by the
original suspend-aware host grant. The existing 30-second CONTROL receipt is
joined with an independent original BOOTTIME interval. Suspend, reattachment,
host-process restart and a new native boot do not renew these bounds. A host
boot-epoch change invalidates native-origin continuation.

Only complete authenticated idle DETACH, flushed ACK, tty exclusivity release
and actual descriptor close permit reentry. EOF, an illuminated display or a
remaining endpoint does not prove it. The resident command-stop latch and
malformed/authentication/clock/exhaustion failures retain their existing stop
behavior; there is no automatic listener/service/module/DRM/USB restart.

`NATIVE_CLOSED` is a timestamped, rederived past native-health snapshot. It
records A as available and untransferred, the original target and native image,
the final native boot and ordinal/nonce history. It promises no future
responsiveness or automatic kernel-stall recovery. Later operations need current
authority and fresh exact health. Native admission, experiment outcome, normal
restoration, Android return and final health are separately reported.

## Failure, recovery and interrupted reporting

Any unexplained effect, authentication, health, command, transport, clock or
terminal failure stops further native roles and closes research under that
grant. The only subsequent partition effect is its original exact A, at most
once, with current exact Download/target/artifact binding and attendance. When
software return is unproved, physical Download is required; this is not
demonstrated automatic recovery. Expiry does not cancel that already bound A
fallback or final-health responsibility.

The request separately freezes the execution sources actually used for A
recovery: the common transport/archive/raw/health closure, baseline and console
owners, Android identity reader, boot verifier, lane/USB departure readers,
declaration reader and common/target/profile authority. They must still match
before the first A dispatch. Recovery does not reopen N/E build inputs or
candidate APs. A itself is reopened and verified at that dispatch; after proven
A completion, final health does not require the old AP to remain available.

Every role has an exclusive intent before delivery. Missing or uncertain
completion after intent is consumed and cannot replay. After a proven A
transfer, continuation performs only bounded exact rooted FYG8 final health.
Raw read failures retain their evidence and may use a new bounded read-attempt
directory. Missing/uncertain A completion parks for operator intervention. An
interrupted experiment never resumes E or its normal N restoration.

Complete raw/close proof of a native terminal permits only H0 terminal,
admission and owner-release repair; reporting failure must not cause another
device transition. Android-origin reservation may abort with zero effects only
before any device intent. Native/physical-Download origin already owns a
recovery responsibility and cannot use that abort. Each operation retains one
structured terminal, append-only journal and private bounded raw evidence.

## Review and activation

Independent review covers this separate common exception, target adoption,
closed role/profile declaration and reachable owner/factory/guard/archive/
descriptor/raw/recovery consumers. H0 qualification must exercise actual
generated C and retained replay, both profile routes, distinct N/E/A binding,
ordinary registry consumption, fresh terminal links, expiry/suspend and cuts
around every E/N/A intent, delivery, result and terminal. Real AArch64 artifacts
must be deterministic A/B builds with actual boot-only AP decoding. Full N/E
requests and terminals must reopen within the existing structured-record bound.

Current source-bound independent PASS_GO is required before live grant opening.
It qualifies the capability, not a run or baseline. Fresh attended bootstrap
qualification remains required before normal N reuse; the first distinct E
roundtrip remains live-unproved until executed and closed under its exact grant.
Ordinary F1 and every other target keep their existing no-repeat, recovery,
partition, private-evidence and physical-attendance boundaries. This exception
adds no unattended authority, persistent-data lane or arbitrary command scope.
