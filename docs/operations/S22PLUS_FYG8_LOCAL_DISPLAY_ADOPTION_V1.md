# S22+ local display candidate adoption V1

Status: **H0 implementation and candidate builds complete; no device grant.**
Target: SM-S906N / g0q / S906NKSS7FYG8. P384 / v0.2.0-rc.2 adopts the
reviewed direct sources, local-display-v1 lifecycle and compatible observer.

This unit uses the ordinary single N candidate and single exact A Android
rollback path. It does not select, renew or alias the consumed P383 same-N
restoration exception. Native-to-native qualification remains separate future
work. No standing native installation or unattended recovery is established.

The platform bootstrap is taken from the immutable P383 emitted-source closure.
The new build explicitly replaces its native helper and publication boundary,
injects the fresh run identity through the existing ARM64 compiler, and applies
the existing same-length raw run-ID/IKCONFIG identity transform to the kernel.
It preserves the rest of the platform, module bytes and boot inventory. Both
complete A/B packages must match and pass independent boot-only decoding.

Candidate byte inputs are the builder's explicit SOURCE_KEYS: direct C/templates
and generator, candidate declaration, build/identity code, fixed census producer,
compiler/packager and boot reader; the immutable platform source/boot/Image,
toolchain, module plan and census inputs are also retained and bound. Freeze
these before qualification. A changed candidate input requires fresh intent and
qualification under the existing target source-identity rules.

Host observation, CONTROL storage, static/promotion readers and policy documents
are separately pinned in the execution closure. A host-only repair can preserve
the AP only after proving unchanged candidate SOURCE_KEYS; it still requires
review of the changed reachable execution closure. Historical pins and results
are never repointed to new source bytes.

The retained image/archive helpers still execute historical source loaders.
Their explicit artifact-only closure is bound, including dynamic source reads;
the builder does not regenerate the historical runtime. The initial codec's
eight observer sources and lazy record/census dependencies are also explicit.
The live execution mapping contains the same build and Carrier roots used by
static verification. AST imports alone are not treated as complete closure.

The native session retains its existing ten-minute limit. This candidate's
host observation budget is 60 seconds with one fixed native-health EXEC and
fresh idle STATUS, then at most one optional HUD EXEC. No operator-plan command
is admitted. The optional command is not counted as operator-plan work. If its
full budget cannot fit, the observer omits it and uses CONTROL5; otherwise it
uses CONTROL6. The durable intent binds that actual sequence and both boot
identity semantic fields, nonce, target endpoint and lane before the first byte.

Stages61/62 report cached before-auth RAM preparation. Native health, HUD
acquisition, reported DRM flips, physical pixels, CONTROL acceptance, exact
Download arrival, A rollback and final Android health remain separate facts.
HUD failure or omission does not supply or invalidate the fixed health proof.
Authentication/framing/transport failure stops the session without replay.

H0 completion requires actual generated C/observer and ordinary owner/raw-reopen/
terminal-result tests, including optional HUD failure/omission and pre-CONTROL
failure, plus current ARM64 A/B package/static/bundle verification and one
independent review of changed connections. Existing unchanged component reviews
and checks are reused. No new physical device action is part of H0 completion.

Any later device run requires the ordinary current preparation, exact rollback,
physical attendance and finite matching F1 authorization. READY publication and
PASS_GO qualify artifacts/capability only; neither is such authorization.

The static tool can create a fresh private review bundle with `--out`. It runs
the actual common bundle and execution-closure readers. This is H0 preparation,
not a live prepared run or publication to the active manifest directory. The
review evidence and current qualification are summarized in the
[P384 H0 report](../reports/S22PLUS_FYG8_LOCAL_DISPLAY_ADOPTION_H0_2026-09-10.md).
