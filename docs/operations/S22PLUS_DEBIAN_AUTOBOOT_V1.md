## Finite ownership and return

One returned attended grant binds one fresh N, exact original A, target,
reviewed sources, qualified artifacts, pinned tools/SSH credentials, usable
physical Download recovery, one operation and 3600 original host BOOTTIME
seconds. No E, native baseline admission, prior tail, reentry, reconnect, HUD,
installation, repair, package workload or arbitrary command is included.

```text
healthy original A -> Download -> one N (owns all automatic startup)
  -> Debian initial shell PID1 / logger + prefix68 + UFS8
  -> complete protected root admission / first bounded file lifetime
  -> six remaining clients / checked sync, unmount and RO restoration
  -> settled children / checked RAM receipt / second complete protected admission
  -> one installed-root RW lifetime / RAM witness / installed SysVinit
  -> rcS / rc2 / first g1 NCM attempt / cron and sshd / 120-second local proof
  -> bounded same-boot pinned SSH evidence and health / one fixed shutdown
  -> attended physical Download / one original A / full Android32 health
```

The unique N transfer intent consumes all automatic preparation, both declared
native_data writable lifetimes, root transition, service startup, bounded
records and the one gadget attempt. There is no host REQUEST, CONTINUE, START
or RELEASE. Their absence is specific to this newly reviewed owner, not a
waiver of the predecessor's gates. Uncertain transfer/startup never replays.
The existing V3 owner, global candidate consumption and append-only journal
remain authoritative. A completed transfer or result may be reconstructed
from its original raw evidence; reconstruction performs no device action.

The device uses a single absolute 300000 ms CLOCK_BOOTTIME deadline, including
early preparation, both admissions, transition and 120-second observation.
No phase renews it. The host's read-only observation ends 360 seconds after
the original successful N transfer completion and before the grant deadline.
Before preflight and at the two existing N launch checks, reuse the file lane's
remaining-budget rule: more than 240 seconds for transfer, 360 for observation
and 600 for physical return must remain. This applies only before N; it never
blocks the original A recovery or renews a consumed budget.
USB observation has at most 180 samples, spaced by up to two seconds; fixed
SSH evidence and health have at most 180 and 30 reads within that same window.
Read failures retain bounded raw captures and may consume the next read only.
Malformed authenticated evidence stops the path. One separately journaled
fixed SSH shutdown is never retried after intent or uncertainty.

Normal return requests physical Download within at most 600 seconds and within
the original grant. Any failure retains the owner for the existing attended
original-A recovery. One A applies across normal and recovery paths. After
proved A, only remaining health/closure may continue. Full original boot/root,
changed boot, Android32/GPT health and durable closure are required. Original A
does not roll back native_data or establish that its filesystem is clean.

## Initial ownership and two admitted filesystem lifetimes

The initial `/init` is Debian's packaged shell as actual PID1, with the retained
physical `sh /init` parent-measurement ABI. Sequential fixed children use the
storage-first declaration: stock logger, retained prefix68, eight UFS modules,
then six clients. Each selected module is checked before insertion and rehashed
on its actual insertion descriptor. Fixed provider barriers, child settlement,
source measurements and bounded checked RAM logs remain required. The UFS
initialization and exact partition/GPT discovery adopt [UFS V1](S22PLUS_NATIVE_UFS_V1.md).
No native manager, display preparation or thermal worker is inherited.

Both admissions retain exact UFS/LU0/GPT binding, partition-only RAM RO with
ioctl/sysfs readback, clean ext4 without recovery/orphan state, fixed unprivileged
checker, installation markers/witness and complete immutable-root comparison.
The finite post-P410 mutable rules from [handoff V2](S22PLUS_DEBIAN_HANDOFF_V2.md)
remain except for canonical boot-count values 1 through 99999 followed by one
newline, allowing the existing installed service to increment at most to 100000.
Absent optional boot count retains its existing meaning. No arbitrary file,
wildcard history, journal replay, repair, formatter or archive extraction is added.

One exact prior early evidence file may be included in the new immutable table
only with its privately sealed path, root-owned 0600 single-link metadata, size
and SHA-256 derived from the authenticated closed P430/P431 retrieval. It is
read-only historical input, not proof of the current boot. Old tables, approvals
and consumed artifacts retain their original bytes and provenance.

The first lifetime creates only `var/lib/lab/s22-early-<sealed-run>`, exclusively,
root-owned 0600 with one link, at most 16384 bytes. It adopts the storage-first
checked header, six client begin/end pairs and final pre-unmount record. Every
record has checked write, synchronization and readback. After complete writer
cleanup, checked unmount, partition RO restoration and post-checks, a checked
0400 RAM copy is published. It is not published on incomplete cleanup. The
supervisor must also settle successfully before PID1 execs the automatic entry.

The entry checks actual PID1, no children or other userspace, only stdio
descriptors, the complete same-boot/source-authenticated early receipt and the
unrenewed deadline. It preserves the first phase's empty protected work tmpfs.
Second admission requires native_data already RO=1 and repeats the complete
root checks. Its sole new current-root extra is the exact newly owned early
file, with checked metadata and content equal to the authenticated RAM copy.
It does not use an admission rule requiring that file before its creation.

After second admission, ordinary protected-root unmount, partition-only RAM RO
clear/readback and a fresh normal RW mount begin the second and final lifetime.
The exact RAM witness, mount transition, installed-init/source checks and child/
descriptor restrictions remain. No fd may retain the old root. Transition
evidence uses a bounded anonymous tmpfs memfd, not ACM: it is frozen with seals,
copied and checked under the new RAM `/run`, then closed before installed init.

## Local services, one USB attempt and proof

The installed hooks record their own identity and automatic start, run and reap
fixed rcS/rc2 children, then check actual same-boot init, cron and sshd in 13
samples over at least 120 seconds. The RAM crontab is empty. The service log is
the distinct exclusive `var/lib/lab/s22-evidence-<sealed-run>`, root-owned 0600,
one link, with a 256-byte header and at most 120 chained 128-byte records
(15616 bytes). Synchronization, parent synchronization and readback remain
mandatory. Revision 5 has its own `S22PLUS-FYG8-DEBIAN-AUTO-DURABLE-v1` domain,
absolute deadline and no transport-loss or host-release events. The early
record and transition domains are respectively
`S22PLUS-FYG8-DEBIAN-AUTO-EARLY-v1` and `S22PLUS-FYG8-DEBIAN-AUTOBOOT-v1`.
Authentication proves the named local records, not an external host request.
After abrupt power loss, successful fsync may leave the latest file metadata
in JBD2 rather than its home blocks. A reader that does not replay the journal
can therefore see an earlier valid prefix. H0 recovery of a regular VM-file
copy may establish stored local records, but grants no physical replay and
proves neither live access nor a clean shutdown of the original filesystem.

The fixed rc2 RAM overlay attempts the first `g1` directly as NCM before sshd.
It requires an empty gadget inventory, claims an exclusive RAM attempt marker,
creates one fixed configuration/function, assigns the sealed addresses and
identity, requests the fixed role, binds one exact UDC with readback and brings
up the fixed network. There is no early ACM, second gadget, detach/rebind loop
or setup retry. Partial setup remains consumed. A failed network script returns
failure to ordinary rc processing; local service observation may still succeed.
This does not prove NCM or SSH. Required identity, storage, child, service and
deadline failures park without another attempt.

The forced SSH command permits only existing health/shutdown and one fixed
`evidence` read. After local completion it emits the actual current boot and
three fixed bounded files: early copy (16384), runtime (16384) and RAM transition
(262144 bytes), in a strictly bounded envelope of 400000 bytes. No caller path
or shell is accepted. The host validates full MAC chains, source/run/boot joins,
root witness, local services and independent SSH health under pinned target
keys and exact USB topology/identity/MAC binding before claiming live access.
The existing ephemeral host network configuration and cleanup owner are reused.

Initial PID1, checked pre-unmount record, installed PID1, local service runtime,
host receipt, live SSH, shutdown request and final Android health are separate
facts. Missing or partial evidence is not non-execution proof. No clean native
shutdown is inferred solely from an accepted SSH shutdown request. If SSH is
absent, physical return still proceeds through the retained recovery owner;
later native_data retrieval requires its own separately qualified reader and
fresh finite grant. It is not part of this operation or a prerequisite for
return. Existing bounded same-returned-boot retained-log D0 remains available
only under its own unchanged profile after complete healthy closure.

Kernel stalls cannot be interrupted by userspace deadlines. This profile
