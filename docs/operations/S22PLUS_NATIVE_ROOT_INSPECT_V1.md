# S22+ native root inspection V1

Status: **REVIEW_GATED_CAPABILITY**

This fixed inspection applies only to operator-owned
`SM-S906N/g0q/S906NKSS7FYG8` and the retained Android32 layout. It implements
stage 2 before any prospective Debian chroot or PID 1 handoff. Its common and
target adoption, current independent review, qualified actual artifacts,
healthy exact Android entry, usable physical Download recovery and one returned
finite attended grant are required. Preparation and this definition grant no
experimental boot transfer.

## One operation and original recovery

The existing V3 owner runs only `root-inspect`, in one operation of at most
1800 original BOOTTIME seconds:

1. Exact fresh Android health, one Download request and measured departure.
2. One globally unconsumed inspector N boot-only transfer.
3. First-boot authenticated native health, one fixed inspection EXEC, DETACH
   and actual descriptor close.
4. Fresh same-boot native health/CONTROL and measured Download departure.
5. One exact original-A boot-only transfer and final rooted Android health,
   bracketed full GPT and Android32 statfs verification.

The inspector profile is exclusive to this graph. There is no E, N admission,
bootstrap, N reuse, prior native tail, reconnect, HUD selection, second
inspection or additional operation. This does not relax V3's two-installation,
four-session baseline admission. N is a one-shot observation image.
The source-bound review uses `s22plus_native_root_inspect_v1_review.json`;
other lanes' review records and all consumed artifacts retain their identities.

The fixed inspection includes a kernel control, so its authenticated EXEC has
an exclusive durable intent before dispatch. The intent binds command bytes,
run, nonce, boot identity and sequence. Once intended, an interrupted command
cannot be retried. The candidate claim and all P399/P400/P401 filesystem and
installation claims remain consumed. Absence of Debian markers does not release
any claim or prove that installation never began.

Any uncertain execution or required native health ends research and retains
the existing one-shot original-A recovery owner. Actual physical Download is
required if normal native CONTROL is unavailable. Timely endpoint binding and
the current V3 same-host-boot recovery restriction remain unchanged. After
proved A transfer only health/report continuation is allowed; A is never
resent. A restored Android boot does not repair or qualify native_data.

## Sealed read-only inspection

The native image retains the previously qualified UFS/drain/ACM runtime and
adds only a static inspector and a bounded comparison table. It contains no
rootfs archive, filesystem formatter or checker payload. It never chroots,
executes an installed file, loads a Debian service, extracts an archive, mounts
read/write, repairs a filesystem, changes GPT or accesses userdata contents.

The fixed helper binds entry 41, 4096-byte LBAs 12,115,456–62,305,023,
205,576,470,528 bytes; the same complete primary/backup GPT, UFS controller/LU0
ancestry, kernel partition maps, filesystem UUID/features and original witness
are retained. The only device nodes it creates are its checked LU0/native
aliases in private RAM `/dev/.s22-ext4-v1`. LU0 reads are confined to the sealed
six initial/nine final metadata blocks. No whole-LU write descriptor is opened.

After exact endpoint/GPT binding, `BLKROSET=1` on **only the native partition**
sets its kernel partition policy. `BLKROGET` and its sysfs read-only field must
both confirm one before mount. This RAM-only control is part of the reviewed
operation, not a disk-data mutation or a generic ioctl capability. The helper
never clears the flag; it remains until the original-A kernel boot.

This is a permanent invariant of this inspector: retained FYG8 ext4 can perform
orphan cleanup, or record filesystem errors in the superblock, despite an
initial read-only mount. `ro,noload,nodiscard` alone is insufficient. The exact
partition block protection precedes every filesystem mount. New kernel/ioctl
semantics or changes to this mount path require independent review.

The original exact clean-superblock guard remains the mount prerequisite,
including no RECOVER bit and zero orphan head. A validly identified but dirty,
recovery-needed or orphan-bearing filesystem is reported without mounting it.
Unknown identity/features/checksum stops the observation. No new checksum or
normalized clean state is ever written to storage.

A clean filesystem is mounted once in the helper's private mount namespace
with `MS_RDONLY|MS_NOSUID|MS_NODEV|MS_NOEXEC` and `noload,nodiscard`. The actual
mount's device, ext4 type and flags plus the partition RO state are verified.
The native PID 1/ACM controller remains outside this mount namespace.

Inspection records start/completion marker state, witness state, bounded tree
metadata counts/digest, and file/link/owner/mode comparisons against the exact
retained P401 archive. The full installation table and its boot-input subset
are distinct. Changed mutable files do not imply damaged immutable boot inputs.
Reads use held directory descriptors without following symlink ancestors;
unknown filenames and contents are not emitted. Limits are 20,000 entries,
32 levels, 512 MiB of known regular-file hash input, 32 digest-only mismatch
samples and 64 KiB of command output. No command or data path is caller selected.

One ordinary unmount, private alias/mountpoint cleanup, unchanged complete
superblock/GPT readback and retained partition RO are required for a completed
mounted observation. A known synchronous failure may make one owned cleanup
unmount; a failed normal unmount is never repeated. There is no force/lazy
unmount or second helper invocation. The command deadline is 240 seconds
within one 300-second observation and the unchanged grant deadline.

## Proof and preparation

An absent/partial/mismatched root or deliberately skipped dirty mount is a
completed negative finding only when its complete raw command and cleanup are
proved. It grants no installation, recovery write or chroot. Command timeout,
truncated output, inconsistent accounting, missing cleanup or protocol
uncertainty is NO_PROOF and stops research. Even a complete file match proves
neither Debian process execution nor PID 1 handoff.

H0 qualification must join actual A/B packaged bytes, sealed table/target and
the source-bound independent review. Real ARM64 Linux VM tests use writable
private regular-file backing disks and exercise block RO control, actual mount,
file observations and unmount, including ext4 read-error and dirty-state
cases. Compare the full allocated extents, positions, size and mtime before
and after each run. VM board discovery is explicitly substituted and does not
prove Samsung boot or target mount.

The foreground preparation profile reuses only the existing fixed Android
root-health brackets, shell-v2 check, full GPT census and Android32 statfs
read on the exact healthy original-A target. It cannot mount native_data,
read its files, set block RO, change mode or transfer an image. A failed pure
read may be freshly reobserved with all old raw captures preserved. Preparation
does not open or renew the finite grant; execution repeats fresh health.
