# S22+ Debian-owned early boot V1

Status: **REVIEW_GATED_CAPABILITY**

Only `SM-S906N/g0q/S906NKSS7FYG8`, the retained Android32 layout and sealed
entry-41 native_data are selected. This is V3's `debian-early` operation with
runtime profile `debian-owned-early-v1`. It qualifies Debian initramfs-tools'
initial shell PID1 and fixed platform/storage preparation, not installed Debian
init, a complete root filesystem, native admission or a persistent service.
No older native, Debian, journal-recovery or evidence grant activates it.

## One operation and original recovery

One returned **attended**, one-operation, 1800-second grant binds a fresh
boot-only candidate, exact physical target, qualified source/artifact closure,
authentication key, demonstrated physical Download route and original Android
A. The candidate must be globally unconsumed. There is no E, native admission,
prior native tail, reentry, reconnect, HUD or additional experiment.

The existing V3 Session owns global exclusion, consumption, append-only
intents and final closure. Its reviewed target adapter performs the existing
Android-to-Download control, exact measured boot-only transfer, and original-A
transfer/final Android32 health. A dedicated fixed evidence action bypasses
native console/health/CONTROL; it does not impersonate those protocols.

The candidate-transfer intent consumes all automatic boot preparation,
including module initialization, partition RAM RO and fixed gadget setup,
before transfer dispatch. Evidence retrieval cannot start/repeat preparation.
The observer accepts one authenticated challenge and sends one bounded result.
There is no request that executes a shell, changes mode, releases a gadget,
reboots, shuts down or supplies a path. No automatic observation retry is
selected. Interrupted reads retain their raw prefix and original owner.

Normal steps are:

`healthy original A -> Download -> candidate -> early evidence -> physical Download -> original A -> Android32 health`

The host waits at most 90 seconds for its exact candidate endpoint and at most
60 seconds for authenticated evidence, within the original grant. The device
child's own evidence lifetime is at most 300 BOOTTIME seconds after entry.
Once observation completes, the coordinator immediately requests attended
physical Download. Its explicit return phase is bounded by the earlier of
600 seconds and the original grant deadline. Exact machine-measured Download
identity remains mandatory before the one A transfer. A returned screen label
or host timeout cannot replace that predicate.

An uncertain transfer, incomplete result, unknown cleanup or failed required
health ends research and retains the original attended A recovery. Expiry of
normal work does not cancel that recovery; the existing same-host epoch and
frozen recovery-source rules apply. An intended A transfer never repeats.
Proved A followed by a reporting/health problem permits only the existing
health-only or H0 closure continuation. No success/failure path leaves a
standing native/deferred session. Physical recovery is required even after a
successful early proof; the child has no Download command.

## Debian ownership and fixed hardware scope

The qualified boot carries Debian's packaged shell `/init` with its declared
small early-device hook. The shell remains PID1 in the original boot namespace
while it executes the preparation and evidence children sequentially. Neither
child can run as PID1 or with a parent other than PID1. The observer measures
PID1's executable bytes and command line, `/init` bytes, the preparation helper
bytes and current kernel boot identity. The fixed host reader checks those
facts against the actual boot archive and same-boot RAM record.

The preparation keeps the exact retained 73-module FYG8 platform order and the
eight modules from the existing UFS declaration. Each file has fixed bytes,
name and parameters; all files are checked before the first insertion. Each
insertion uses one pinned fd and flags zero, with checked RAM BEGIN/DONE
records and current module presence. EEXIST and partial insertion stop;
no module is retried or unloaded. The same ordinary controller/PHY/ICE,
UFS attribute/feature, HPB and SCSI discovery effects already enumerated by
[S22+ native UFS V1](S22PLUS_NATIVE_UFS_V1.md) are retained. This is F1 hardware
initialization, not a zero-device-write or D0 claim. No caller-selected SCSI,
RPMB/key, partition-data writer, discard or formatter is added.

The evidence child, after complete selected module presence, creates only the
first fixed configfs gadget `g1`: Samsung research VID/PID, candidate-bound
`S22E3` serial, one `acm.usb0` function and the exact FYG8 peripheral-role/UDC
binding. The tty is opened and normalized before UDC publication. It uses the
existing exact host topology/serial/interface/driver and exclusive-tty holder
checks. No second gadget, NCM interface, network manager or SSH setup exists.
A failed setup/bind never repeats and remains physical-recovery-only.

This profile does **not** inherit the former native thermal service, native
health assertion or watchdog-petting claim. The retained kernel and fixed
watchdog/platform modules are unchanged, but the native console/renderer and
thermal workers are absent. The first trial is bounded and physically
attended; actual stability is experimental evidence, not an assumption of
safe quiescence. A userspace deadline cannot recover a stalled kernel syscall.
A parked shell, missing USB or lost RAM record does not establish power state,
thermal health or automatic recovery. The operator must retain the usable
physical return path throughout. No speculative replacement daemon is added.

## Protected metadata, not root admission

The child binds the exact UFS controller/LU0, partition 41, native_data and
userdata extents, block size, holders and mount state. It creates only its
exclusive 0400 block aliases in tmpfs, compares the sealed initial six and
final nine GPT blocks, sets only entry 41's RAM BLKROSET=1, and checks ioctl and
sysfs RO. It reads only the 1024-byte primary ext4 superblock, verifies the
original checksum/identity, and classifies clean versus dirty from that read.
Repeated GPT/superblock/RO readbacks and owned-alias cleanup close the result.
Partition RO is never cleared. Block files are opened only read-only.

There is no filesystem mount, journal replay, repair, root-tree/file read,
installed-code execution, archive extraction or data write. Clean metadata is
not complete ext4 integrity or immutable-root admission. Authenticated dirty
metadata is an expected scientific result, not permission to repair, repeat
or start installed Debian. P415's dirty-root observation and every historical
consumed action retain their meanings.

## Evidence and qualification

The exclusive 0400 RAM file under root-owned 0700 tmpfs `/run/initramfs` is
bounded to 64 KiB/256 checked records, with construction and kernel boot
identity. Failed/short evidence writes stop later preparation effects. The
read-only observer returns candidate/challenge-bound HMAC frames under a
separate domain, actual parent/executable facts, bounded record chunks and a
terminal digest. The host validates exact order, complete framing, helper
status and semantic result before claiming `PASS_DEBIAN_EARLY_OBSERVED`.
That verdict does not itself imply preparation or clean metadata success.

Raw RX/TX and every failure prefix remain private. Complete early proof,
module/storage result and final Android health are separate. RAM evidence is
not persistent or externally proved until authenticated capture; absence after
reset never proves non-execution. This profile authorizes no persistent
receipt writer, pstore write or arbitrary post-return retrieval.

Independent review covers common/target adoption, actual Debian/vendor
archive composition, fixed gadget and parent identity, frame producer/consumer,
V3 lifecycle integration, interruption/no-replay and original recovery.
Representative ARM64 VM tests exercise actual PID1, combined vendor/Debian
extraction, file checks, block ioctls and authenticated frames with hardware
substitutions labelled. They do not prove real module/UFS/USB behavior.

Current source-bound review and actual boot/AP qualification precede the
existing fixed foreground Android preparation: root/boot/supporting-partition
health brackets, shell-v2, exact GPT and Android32 statfs. These preparation
reads need no repeated per-read approval or attendance and change no mode or
image. A fresh returned concrete grant and actual attendance are still
required before the candidate experiment. No definition or PASS_GO alone
opens that grant.
