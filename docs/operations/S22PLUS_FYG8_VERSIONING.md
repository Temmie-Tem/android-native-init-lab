# S22+ FYG8 버전·후보·실행 명명 규칙

적용일: 2026-09-09. 운영자와 합의한 새 명명 규칙이다.
대상은 `SM-S906N / g0q / S906NKSS7FYG8`이며, 새 실험의 주된 표기에 적용한다.
기존 [A90 버전 정책](VERSIONING_POLICY.md)은 변경하지 않는다. 다른 대상에
적용할 때에는 별도로 채택하며, 대상 간 버전 번호·검증·권한은 공유하지 않는다.

이 문서는 이름과 산출물의 대응을 정의한다. 기기 동작, 재실행, 상주 설치,
롤백 목적지 변경이나 새 실행 경로를 승인하지 않는다. 해당 동작은 기존
AGENTS.md, 대상 계약과 실제 실행기의 바인딩·승인·소비 규칙을 따른다.

## 기본 표기

사람이 보는 이름:

```text
v0.2.0-rc.1 — native 베이스라인 왕복 복원
```

개별 실행의 표시용 식별자:

```text
s22plus-fyg8-v0.2.0-rc.1-run-001
```

| 요소 | 의미 |
| --- | --- |
| `s22plus-fyg8` | 대상 기기·펌웨어 계열 |
| `vMAJOR.MINOR.PATCH` | 기능 버전 또는 목표 버전 |
| `-rc.N` | 해당 목표 버전의 후보 번호, 1부터 증가 |
| `-run-NNN` | 해당 후보의 실행 번호, 001부터 증가 |
| 설명 문구 | 실행 전에 정한 구체적인 실험 목적 |

파일용 표기에는 공백 대신 하이픈을 사용한다. 실행 번호는 최소 세 자리이며
999를 넘으면 자릿수를 늘린다. 새 후보에서는 실행 번호를 001부터 시작한다.
번호는 같은 대상·후보 안에서 중복 사용하지 않는다.

## 번호 증가

| 변경 | 다음 표기 예시 |
| --- | --- |
| 같은 목표의 실패 수정 또는 변경된 후보 | `v0.2.0-rc.1` → `v0.2.0-rc.2` |
| 동일 후보의 허용된 추가 실행 | `...-rc.2-run-001` → `...-rc.2-run-002` |
| 확정 버전의 작은 수정·개선 | `v0.2.0` → `v0.2.1-rc.1` |
| 주요 기능 단계 추가·큰 주제 전환 | `v0.2.x` → `v0.3.0-rc.1` |
| 합의한 서버 운영·복구 기준을 충족한 첫 운영 버전 | `v1.0.0` |
| 이후 사용 방식이나 호환성이 크게 달라지는 전환 | `v2.0.0-rc.1` |

마이너 증가 시 패치는 0으로, 메이저 증가 시 마이너·패치는 0으로 시작한다.
각 목표 버전의 후보 번호는 `rc.1`부터 시작한다. 커널 교체는 자동으로 메이저
증가가 되는 것은 아니며, 개발 단계와 운영·호환성에 미치는 영향을 판단한다.

코드·이미지 또는 실행에 영향을 주는 바인딩이 달라지면 같은 후보를 덮어쓰지
않고 새 후보를 만든다. 동일 입력으로 재현한 빌드가 동일 산출물과 실행 바인딩을
가진다면 새 후보로 간주하지 않는다. 설명 문서 수정이나 변경 없는 후보의
호스트 검사만으로 후보·기능 버전을 올리지 않는다.

실행 번호는 실제 실행 시도를 식별한다. 실행 전 중단도 해당 시도의 결과로
남기며 번호를 재사용하지 않는다. 결과를 다시 파싱하거나 보고서를 보완하는
것은 새 실행이 아니다. 기존 실행기의 복구 재개 역시 원래 실행의 일부다.

실행 번호 증가는 재실행 권한을 만들지 않는다. 이미 소비된 후보·실행의 재생이
금지된 경로에서는 번호만 바꿔 다시 실행할 수 없다. 기존 규칙이 새 후보나
승인·준비를 요구하면 그 조건을 먼저 충족한다.

## 후보에서 최종 버전으로 확정

```text
v0.2.0-rc.1 / run-001 → 실패
수정
v0.2.0-rc.2 / run-001 → 목표 기준 충족
v0.2.0 ↔ 성공한 rc.2의 동일 산출물
```

성공 조건은 실행 전에 정한다. 그 버전이 약속한 기능, 필요한 실패 처리,
복귀·롤백 및 최종 건강 상태를 정확한 산출물과 연결해 확인한 뒤 확정한다.
실패 경로는 구체적인 위험에 맞춰 호스트 검증과 실기 검증을 구분한다.
모든 버전에 일률적인 반복 횟수나 장시간 운전 시간을 추가하지 않는다.

확정 시 새 이미지를 빌드하지 않고 검증된 후보의 해시와 증거를 연결한다.
후보 이름·원시 증거·소비된 실행 기록은 소급 개명하거나 덮어쓰지 않는다.
실패한 후보도 보존한다. 버전 확정은 해당 기능 범위의 기준 충족을 뜻하며,
미검증 상황의 안정성이나 상주 베이스라인 승격을 뜻하지 않는다.

작은 기능 목표를 완료하면 해당 버전을 확정하고 다음 목표로 이동한다.
같은 목표의 시행착오는 `rc.N`과 실행 기록에 남긴다. 번호를 작게 유지하기
위해 성공 조건을 낮추거나 실패 이력을 생략하지 않는다.

## 검증 상태와 기록

버전·실험 목적·실행·결과를 별도 항목으로 남긴다. 기존 기록 형식을 활용하며,
명명 규칙만을 위한 새 실행기나 승인 단계를 만들지 않는다.

```text
대상: s22plus-fyg8
버전/후보: v0.2.0-rc.2
실험: native 베이스라인 왕복 복원
실행: run-001
내부 실행 ID: 실제 실행기가 발급한 기존 ID
산출물/바인딩: 정확한 이미지·실행 소스 해시 또는 해당 기록의 참조
기능 검증: 결과와 근거
복구/롤백: 결과와 근거
최종 건강: 결과와 근거
관찰 및 미검증 범위: 별도 명시
```

`PROVED`, `OBSERVED`, `NO_PROOF` 등 기존 증거 구분을 유지한다. 화면에 보였다는
운영자 관찰을 기계적 픽셀 증명으로 바꾸지 않으며, 정상 롤백이 기능 성공을
대신하지 않는다. 장시간 운전·반복 부팅·커널 정지 복구 등은 실제 확인 범위만
기록한다. 버전 번호 자체가 검증 상태를 대신하지 않는다.

## 기존 식별자와의 연결 및 첫 버전

기존 P 번호, V 번호, 내부 run ID, 파일명, 매니페스트, 승인 바인딩과 저널은
유지한다. 새 버전은 먼저 사용자 표기와 대응 기록으로 도입한다. 내부 실행기
식별자 변경은 필요한 경우 별도 범위로 검토·구현한다. 이 문서만으로 기존
실행기의 파일명이나 run ID 형식을 바꾸지 않는다.
