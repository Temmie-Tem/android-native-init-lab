# SM-S906N FYG1 기존 RF 보고서 단건 조회 절차

**상태는 H0 설계다.** 대상은 운영자 소유 `SM-S906N/g0q`, 부트로더
`S906NKSS7FYG8`, CP `S906NKSS7FYG1`, AP 보드 리비전 16이다.
목적은 CP EFS에 이미 존재하는 `rfc/rfdevice_report.dat` 한 파일의
바이트를 읽고 QLINK 0 트랜시버의 식별 근거를 평가하는 것이다.

## 조회 허용 여부

FYG1의 파일 읽기 분기와 RF 보고서 생성 분기는 별개다. 보관한 Android
HAL에서 `Idiag::open`의 인자는 콜백이고, 경로를 받는 파일 열기 API는
확인되지 않았다. 실행 중인 라우터를 통해 이 파일을 읽으려면 CP에
진단 요청이 전달된다. 현 [S22+ D0](targets/S22PLUS_FYG8_TARGET_CONTRACT.md#s22-d0)와
[공통 위험 등급](DEVICE_ACTION_RISK_TIERS.md#d0---connected-read-only)은
페이로드 전송을 제외한다. 새 저수준 전송은 공통 위험 등급의
[별도 계약 검토](DEVICE_ACTION_RISK_TIERS.md#escalation-rules) 대상이다.

실기 판단은 **활성화된 정확한 조회 범위, 검토된 실제 호출 경로, 해당
실행에 유효한 권한**을 확인한 뒤 내린다. 설계 검토 결과만으로 이 세
조건을 충족할 수 없다. 현 상태에서는 호스트에 보관한 자료 평가에서 종료한다.

## 한 파일 조회

1. 승인 대상 구현에서 호출자 입력 없이 CP 대상과 파일명을 고정한다.
   순정 접근 검사를 그대로 거쳐 해당 기존 파일을 읽기 전용으로 열고,
   끝까지 읽은 뒤 그 조회가 소유한 핸들만 닫는 경로를 검토한다.
   경로가 다른 객체로 전환될 수 있는지, 실패 처리가 생성·갱신 API로
   이어지는지, 열기와 읽기가 파일 내용이나 저장 메타데이터를 변경하는지
   실제 구현에서 확인한다. 파일을 그대로 보존한다는 조건을 검증할 수
   없으면 실기 요청을 보내지 않는다. 파일 생성·수정, 디렉터리 열거, 다른 파일,
   RF 시험 모드, 진단 로그 활성화, 보안 설정 변경은 범위 밖이다.
2. 기기 접근 전 같은 구현의 성공·부재·권한 거절·잘린 응답·시간 초과
   경로를 호스트에서 대조한다. 검사 대상은 전송 요청 전체와 반환값이며,
   콜백 등록과 해제가 기존 라우터 클라이언트를 밀어내거나 공유 설정을
   변경하지 않는지 확인한다. 대상·조회와 결합되지 않은 이벤트는 원본
   캡처나 로그에 기록하기 전에 폐기한다. 다른 클라이언트 응답을 섞은
   입력에서도 이 동작을 검증한다. 실기에서 사용할 구현과 검토한 바이트가
   일치해야 한다.
3. 실기 실행이 허용된 경우 기존 S22+ 세션 잠금과 소유자 충돌 검사를
   사용한다. 요청 직전에 비공개 기기 식별값·USB 토폴로지, 대상 빌드·보드,
   Android 부팅 및 상태, 기존 USB 구성과 라우터를 확인한다.
   관측한 USB 구성 `mtp,conn_gadget,adb`를 유지한다. 클라이언트 설치,
   USB 기능 전환, 서비스 재시작, 기기 파일 스테이징은 수행 범위 밖이다.
4. 단건 조회 한 번의 제안 예산은 전체 30초, 파일 내용 256 KiB다.
   동일한 파일 버전·거래에 귀속되는 연속 구간만 수용하고 EOF까지
   완전성이 확인될 때만 파일 바이트를 확보한 것으로 기록한다.
   빈 파일은 별도로 표시한다. 부재와
   권한 거절은 해당 CP의 명시적 응답으로 구분한다. 초과·누락·충돌·연결
   단절·불명 응답에서는 중지하고 부분 수신 상태를 보존한다. 중단된
   조회의 재전송, 대체 경로 검색, 보고서 재생성은 하지 않는다.
5. 바이트 확보와 세션 종료는 따로 기록한다. 최초 예산 내에서 이 조회의
   CP 읽기 상태와 클라이언트 콜백이 해제되었고 기존 라우터 사용자 및
   공유 설정이 보존됐는지 확인한다. 구현이 요청마다 상태를 자동 해제하면
   검토된 해제 경로의 완료 응답을 사용한다. 같은 대상·Android 부팅·USB
   구성 및 정상 상태까지 확인되어야 정상 종료다. 해제 또는 최종 확인이
   불확실하면 EOF를 받았어도 종료 미확인으로 남기고, 원래 소유자의
   기록을 보존한다. 별도 재시도·강제 해제·서비스 재시작은 하지 않는다.
   요청 결과, 실제 길이, 수신 바이트의 SHA-256 및 제한된 원본은
   `workspace/private/`의 새 실행 디렉터리에 보존한다. 부분 수신과
   종료 시점의 불확실성도 기록한다. 공개 결과에는 칩 판정에 필요한
   필드만 남긴다. 원본에는 `Serial#` 등의 열이 있다.

## 칩 판정

파일 획득과 실리콘 식별은 각각 판정한다. 파일이 읽혀도 아래 연결이
끊기면 해당 항목을 미확인으로 남긴다. 이 판정에 사용할 수 있는 자료는
조회한 한 파일과 이미 보관된 해당 기기의 근거다.

| 질문 | 채택할 근거 |
| --- | --- |
| 보고서가 이번 **CP 부팅**에서 생성됐는가? | 읽기 시점의 CP 부팅을 식별하고, 보고서 자체의 생성 근거나 그 내용에 결합된 기존 생성 기록을 같은 CP 부팅에 귀속한다. 앞뒤 Android 부팅 ID 일치, 파일 시각, 읽기 성공만으로는 이전 CP 부팅의 파일을 배제할 수 없다. CP 재시작 또는 식별 불가 시 귀속은 미확인이다. |
| 이 행이 QLINK 0 트랜시버인가? | FYG1에서 실제 선택된 보드의 물리 장치와 링크 대응을 행의 식별 필드에 대조해 유일하게 연결한다. 첫 행, AP 보드 번호, 공통 `RF QLink Init Success` 표시는 링크 식별 근거로 부족하다. |
| 칩 ID가 어디서 왔는가? | 같은 CP 부팅·링크의 해당 초기화에서 성공한 하드웨어 읽기와 반환 워드가 확인되면 **실측**이다. 읽기 실패 후 대체 분기가 선택된 기록이 확인되면 **기본값**이다. 둘 다 없거나 기록이 상충하면 **출처 미확인**이다. 생성자와 실패 분기가 모두 `0x39040`을 쓰므로 이 값만으로는 어느 쪽도 선택할 수 없다. |
| `HW_Rev`와 `FAB_SRC`는 무엇을 입증하는가? | 같은 물리 행의 원래 표기와 수집 성공 여부를 각각 기록한다. FYG1은 제조원 조회 실패 뒤에도 표를 출력한다. 실제 읽기·해독 성공과 해당 칩의 제조사 리비전 대응표가 뒷받침될 때만 실측 ID와 함께 SDR735 v2.0 여부를 판정한다. `ril.hw_ver`와 클래스명은 실리콘 리비전의 대체 입력으로 쓰지 않는다. |

FYG1 생산자·읽기 경로와 단말의 기존 관측은
[실기 보드 식별 보고서](../reports/S22PLUS_FYG8_BOARD_AND_CELL_BROADCAST_H0_2026-11-18.md#기존-cp-efs-파일을-읽는-순정-진단-경로)에 기록되어 있다.
