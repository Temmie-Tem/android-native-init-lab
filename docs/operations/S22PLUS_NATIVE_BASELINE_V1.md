# S22+ bounded attended native baseline V1

Status: **REVIEW_GATED_CAPABILITY; no standing device grant or admitted image.**
Target: **SM-S906N / g0q / S906NKSS7FYG8**.

This policy defines reusable normal installation of an admitted native baseline
and a healthy native terminal. P384's completed roundtrip proves its two native
arrivals, exact normal restoration and Android cleanup. It does not prove a
reattachable terminal: its image admits one authentication per boot. The new
`native-baseline-v1` profile therefore requires its own source-qualified image,
complete H0 checks, independent review and fresh attended live qualification.
The first prospective profile is P385 / v0.2.0-rc.3. It is not qualified by
renaming P384 or by changing an old result, approval, installation claim or
V1/V2 exception. Those consumed records remain unchanged.

## Exact delegation and admission

After independent common-boundary review and incorporation by SHA-256, this
policy specializes only the native-baseline owner's normal baseline role:

- An admitted baseline is one exact boot-only AP/member, direct runtime profile,
  source closure, authentication-key identity, target and live qualification.
  Its registration must reopen all of those inputs. A successful flash, banner,
  one health command, ordinary candidate approval or caller label is insufficient.
  Native image/runtime qualification and current host execution review are
  separate identities. A reviewed host-only repair can retain admission when
  all native byte inputs and the image are unchanged and the current reader
  rederives the retained qualification. It requires a fresh host/grant binding,
  never an unconsumed bootstrap of the already registered image.
- Bootstrap qualification installs one previously unconsumed admitted H0 image,
  proves healthy clean detach and fresh same-boot reauthentication, performs one
  declared same-image normal restoration after exact timely Download, then
  proves the second boot and a healthy reattachable native terminal. This whole
  qualification is one original attended grant. Its installation permanently
  consumes the ordinary target/content key. The one qualification restoration
  has a separate one-shot intent; failure never permits another native attempt.
- Only a completed source-bound bootstrap qualification can register the image
  for subsequent normal baseline roles. Later installation/restoration of that
  registered image is an explicit exception to the ordinary content-keyed
  no-repeat rule, within the finite grant below. It never releases, replaces or
  resets the image's original installation claim or a past role's intent.
- Ordinary experimental candidates remain one-shot. This initial owner admits
  only bootstrap qualification, normal restoration of its exact registered
  baseline and exact Android exit/fallback. It does not accept arbitrary new
  experiments, make a failed experiment a baseline or authorize native recovery
  after an unexplained failure.

Each role has its own exclusive intent before delivery and one immutable raw
result. A durable intent with missing/uncertain completion is consumed. A new
run name, path, grant or healthy later observation cannot replay that role.
The original V1/V2 claims and ordinary registry algorithm remain unchanged.

## Finite attended operation

One explicit operator grant binds the exact target, admitted baseline, exact
Android A, review/source/transport identities, operation set and limits. Use a
distinct native-baseline grant entry; never synthesize an ordinary Process-v2
approval or reuse a consumed approval. Physical attendance and usable exact
physical Download recovery remain required during device effects.

A grant permits at most three operation reservations and 600 seconds from
creation. Bootstrap qualification is a single reservation with the two native
roles above. Each reservation includes capacity for one exact Android fallback;
normal completion may instead end in healthy native. Smaller operator limits
are permitted. No operation, authentication, restored boot or later observation
renews the grant. The existing target-session lock and F1 owner serialize device
effects. An unfinished reservation blocks the next one; a native terminal is
validated before releasing its operation owner. A direct Android exit consumes
one reservation; its requested exit and failure fallback share the same sole
A intent, so neither can authorize a second A transfer.

The grant and derived native/observation deadlines use host `CLOCK_BOOTTIME`,
so host suspend consumes their original time. CONTROL retains its existing
30-second monotonic receipt and an independently joined BOOTTIME interval.
Neither a new host process nor suspend/resume renews a deadline. Host boot epoch
encoding is the existing return owner's exact validated representation.

Every normal native role reopens exact artifact/member/source/authority bindings
and fresh starting health. Android entry uses the existing exact D0 profile. Native entry
requires fresh authenticated fixed health on the registered image, the expected
same kernel boot identity and a new nonce. Cached native health is a past
snapshot, never a substitute for that check. No candidate may be flashed over
an unhealthy or unverified starting state. Failed-native A fallback instead
requires its exact current Download/target/artifact and durable recovery binding;
it does not require the failed native component to prove healthy.

A native-origin operation consumes an exclusive link from the previous native
terminal and verifies the same physical target and retained endpoint. Its initial
inventory records an already-present candidate, never candidate absence. The
current guard must freshly observe both required ModemManager ignore properties
on that exact tty. Missing properties stop before AUTH and retain the bound A
fallback; the owner does not trigger udev or change global ModemManager state.
Guard release proves only its helper/rule cleanup, not continuous protection
between owners. Ordinary candidate entry keeps its existing absence baseline.

## Boot lifetime and clean session release

The new profile separates one-time boot preparation from authentication state.
Return modules, RAM root-work preparation and local display start once per boot.
Later authentication reports their cached provenance and rechecks current root
and native health; it does not repeat module insertion or mount creation.

The existing 900-second local lifetime is also the fixed native admission
ceiling for this profile. At most eight authentication sessions are admitted in
one boot. The existing per-read 30-second, per-console 600-second and per-CONTROL
30-second host return limits remain; every session is capped by the original
boot lifetime. No authentication or status request resets that lifetime.
The host also enforces its original grant and per-observation budgets.

Only an authenticated, fully flushed clean DETACH may release one session for
fresh authentication. DETACH requires idle native state with no unresolved child,
output, fault or partial request. It is distinct from Download CONTROL. The host
preserves its intent/ACK and exact descriptor close/reopen evidence, then requires
the same kernel boot identity and a nonce unused in that boot's bounded history.
The descriptor owner records release of tty exclusivity and actual close/reopen;
failed release or close cannot admit another AUTH. It never infers clean detach
from EOF, missing bytes, a disappearing endpoint or a still-visible screen.

An absent peer before any OPEN byte may remain idle within the original boot
ceiling. Consumed OPEN bytes followed by malformed/authentication/transport
failure, failed detach, session expiry or an inconsistent clock stop admission.
No automatic listener restart or renewed authentication follows that stop.
Expiry parks native without an automatic reboot or transfer. A later healthy
read does not erase a stop. HUD observations remain optional and do not establish
native health, physical pixels or continuous liveness.

## Native terminal and Android fallback

Healthy native completion reopens the native image identity, complete raw fixed
health, an earlier clean detach and same-boot fresh authentication proof. The
last authentication must also finish with a complete clean DETACH ACK and an
actually completed host descriptor close. At least one further authentication
admission and positive original boot time must remain at close; an exhausted
last slot, expired clock or uncertain close cannot produce a native terminal.
The terminal is
`NATIVE_CLOSED` with a timestamped native-health snapshot and remaining boot
admission bounds. It records that Android A was available but not transferred.
It is not an ordinary Android `CLOSED`, an unlimited lease or a promise of future
responsiveness. A subsequent operation obtains current authority and rechecks
native health before any control or transfer.

After any unexplained effect/session failure, research ends. The only later
partition effect is the originally bound exact Android A, at most once, after
current exact Download/target binding and continued physical recovery/attendance
are established. Missing/uncertain A completion parks without replay. Recovery
never performs another native role or upgrades a native qualification. Expiry or
withdrawal does not cancel already authorized fallback/final-health work.
After a completed native terminal and ended grant, a new Android exit requires
current authority; no old closed grant supplies standing recovery authority.
If that native has expired or cannot authenticate, the new exact A exit uses
attended physical Download and exact target/artifact binding, without requiring
healthy native execution or attempting another native image first.

An Android terminal requires the existing exact rooted FYG8/original partition
health and Download absence. Native qualification, normal native restoration,
Android fallback and final health remain separate evidence. Each operation
retains one structured result, append-only role journal and private raw evidence.
An Android-origin reservation that fails before any device intent may close
`ABORTED_NO_DEVICE_EFFECT`. Native/physical-Download origin already carries an
explicit terminal/recovery responsibility and cannot use that pre-effect abort.
After an interrupted A transfer, completed raw transfer evidence may lead only
to final health; missing/uncertain completion never transfers A again. Incomplete
read captures remain intact and final health may use a fresh bounded read-attempt
directory. A complete native terminal is repaired/reported without another
device transition. An empty interrupted H0 phase directory or missing initial
lane receipt may be completed from its exact retained operation/target binding;
present malformed, changed or inconsistent records remain a stop.

## Qualification and activation

Review covers this common exception, target adoption, the new profile and actual
factory/guard/descriptor/raw/terminal/transfer consumers. H0 must exercise clean
detach/reattach, cached boot preparation, fresh nonce/same boot joins, finite
lifetimes, raw failure preservation, real writer/reopen limits and cuts before
and after every role intent/delivery/result/terminal. Existing ordinary and
consumed V1/V2 semantics remain covered without repinning their records.

The live capability remains blocked until its exact independent PASS_GO receipt
matches current sources, artifacts and declared limits. Host preparation and
PASS_GO grant no device action. Bootstrap live qualification still requires a
separately returned finite approval and actual attendance. Normal baseline reuse
additionally requires the retained live admission proof; another target or an
unregistered image can never inherit it.

Boot-only membership, forbidden partitions/transports, exact Android recovery,
private evidence and target isolation remain permanent. This policy grants no
unattended execution, stall recovery, persistent data experiment, arbitrary root
command or other-target capability. The finite runtime bounds contain protocol
and resource use; revising them changes the reviewed runtime/profile closure.
